# 数据中心工具栏交互修复设计

## 背景

数据中心工具栏目前在整个数据中心工作区显示“上传数据”，但该操作应只在用户进入“数据集详情”后出现。同时，“导出报告”点击后依赖异步 `window.open`，浏览器可能拦截新标签页，且失败仅输出控制台日志，用户无法判断操作是否执行。

## 目标与范围

- 仅在 `data-center/datasets` 页面且已进入某个数据集详情时显示“上传数据”。
- 在数据集列表、数据登记、数据核验、数据版本等数据中心页面隐藏该按钮。
- 保持点击“上传数据”后进入既有数据登记页的行为不变。
- 让报告导出在浏览器阻止异步弹窗时仍能打开下载页，并对失败提供可见反馈。
- 不修改后端报告接口、数据登记接口或其他页面的信息架构。

## 方案

### 工具栏状态

`WorkspaceFrame` 持有 `isDatasetDetail` 状态，仅在 `route === 'data-center/datasets'` 时允许 `DatasetWorkspace` 通过回调更新它。进入数据集详情时设为 `true`，返回列表或卸载时设为 `false`。工具栏配置使用该状态决定是否传入 action；`Toolbar` 对无 action 的情况不渲染主操作按钮。

### 导出流程

`Toolbar` 在点击时同步调用 `window.open('', '_blank')` 预留标签页，然后发起 `exportReport`。成功后将返回的第一个 URL 写入该标签页；如果没有 URL 或请求失败，关闭预留页并通过页面级可见提示告知用户。保留现有报告类型、PDF 格式和 ref id 传参规则。

## 错误处理

- 浏览器无法创建标签页时仍发起请求，并在成功返回 URL 后使用当前窗口导航作为兜底。
- 接口失败、返回空 URL 或数据集报告不可导出时显示统一错误提示，不依赖控制台日志。
- 导出进行中禁用按钮，避免重复提交；完成或失败后恢复。

## 测试与验收

- 静态/组件回归测试确认：数据集列表不显示上传 action，点击数据集进入详情后显示，离开后隐藏。
- 测试确认导出会预留窗口并将返回 URL 写入该窗口，空 URL 和异常会显示错误反馈。
- 执行 `npm run typecheck`、`npm run build` 和已有 Node 回归测试。
- 对修改后的 `src/App.tsx` 执行 Impeccable detector，确保没有新增界面质量问题。
