# 数据集层级重构设计

## 1. 背景与目标

当前数据中心将“数据列表”和“数据集”作为并列入口，用户无法理解数据集与单条焊缝数据的归属关系。本次调整将数据中心改为明确的容器层级：

```text
数据集列表 → 数据集概览 → 数据列表 → 数据详情
```

目标：让用户始终知道当前数据属于哪个数据集、哪个数据集版本，以及它在训练/验证/测试中的划分。

## 2. 已确认的产品决策

- 采用 A 方案：移除左侧独立“数据列表”入口。
- “数据中心”默认进入“数据集列表”。
- 不使用横向 Tab 作为数据集详情的主导航。
- 数据集概览通过明确的 CTA 进入数据列表。
- 版本、质量、血缘作为概览页中的摘要卡片/操作入口。
- 单条数据详情从数据集成员列表进入。
- 数据登记保留为数据中心操作能力；新登记数据在未归档/待归入状态下可被识别，不强行改变登记流程。

## 3. 信息架构

### 3.1 导航

左侧数据中心仅保留：

- 数据集
- 数据登记
- 数据核验
- 数据版本（如仍需保留快捷入口，应定位为“当前数据”的上下文工具，而非全局数据列表）

推荐进一步将“数据核验”与“数据版本”作为从数据详情进入的操作，不在主导航中承载数据浏览流程。

### 3.2 页面层级

1. **数据集列表**：查看所有数据集、创建数据集、进入某个数据集概览。
2. **数据集概览**：展示统计、质量、版本、血缘摘要；主 CTA 为“查看当前版本数据”。
3. **数据列表**：展示选定数据集/版本的成员数据；支持筛选、分页、切换版本。
4. **数据详情**：展示单条焊缝登记、当前版本、核验状态、数据集归属及后续分析入口。

所有下级页面显示面包屑，例如：

```text
数据中心 / 数据集列表 / 焊接缺陷检测 / 当前版本数据 / WLD-20260815-001
```

## 4. 交互设计

### 4.1 数据集列表

保留现有数据集表格和“新建数据集”按钮。点击整行进入数据集概览，不再直接进入一个与列表混合的详情 Tab。

### 4.2 数据集概览

页面分为：

- 页面头部：数据集编号、名称、任务类型、状态、当前版本。
- 核心统计：样本总数、标注完成度、训练/验证/测试数量、质量分数。
- 首要操作卡：`查看当前版本数据 · N 条`。
- 辅助卡：数据集版本、数据质量、数据血缘。
- 训练入口：仅在“可训练”时启用。

“查看当前版本数据”是进入下一层的唯一主路径，避免用户猜测数据藏在哪里。

### 4.3 数据列表

顶部固定数据集上下文卡：

- 数据集名称
- 当前版本号
- 数据总数
- 训练/验证/测试比例
- “切换版本”入口

列表字段建议：数据 ID、登记编号、数据来源、焊机/工艺、模态、核验状态、数据集划分、更新时间。点击行进入数据详情。

数据列表必须只展示所选数据集版本的成员，不能再调用全局 `/welds` 后在前端过滤。

### 4.4 数据详情

在现有焊缝详情基础上增加：

- 所属数据集
- 所属数据集版本
- 数据划分
- 返回数据集数据列表

核验、数据版本、分析、标注等操作沿用现有“先选择数据”的上下文机制，但选择来源变为数据集成员列表。

## 5. 前端实现边界

- 继续沿用 React + TypeScript + Tailwind 及现有视觉语言。
- 不重写 `App.tsx`，以最小范围调整路由、导航和 `DatasetWorkspace` / `DatasetDetail` 组件。
- 将数据集概览、数据列表、数据详情拆成清晰的页面状态/组件边界；不再使用 `dataset-subtabs` 表达主层级。
- 保留 mock 兜底策略，API 失败时页面仍可展示演示数据。
- selectedDataId 仍用于进入核验、分析、标注等下游流程；新增 selectedDatasetId、selectedDatasetVersionId 表达数据集上下文。

## 6. 后端/API 实现边界

当前已有 `datasets → dataset_versions → dataset_items → samples/data_records` 关系，但 `GET /welds` 不能支撑数据集成员查询。需要新增一个面向数据集版本的成员列表接口，建议：

```text
GET /api/v1/datasets/{dataset_id}/versions/{version_id}/items
```

参数：`q`、`quality`、`split`、`page`、`page_size`。

响应继续使用统一分页信封：

```json
{
  "items": [
    {
      "sample_id": 1,
      "weld_id": "WLD-...",
      "registration_no": "REG-...",
      "split": "train",
      "quality": "通过"
    }
  ],
  "total": 100,
  "page": 1,
  "page_size": 20
}
```

实现时应复用已有数据集版本、样本、数据记录查询逻辑，不新增重复表。若当前表结构无法直接返回完整登记字段，可先返回成员 ID 与焊缝 ID，再由详情接口读取完整记录，但列表应优先一次查询完成，避免 N+1 请求。

## 7. 空状态与边界

- 数据集无当前版本：概览显示“尚未生成固定版本”，主 CTA 改为“创建数据集版本”。
- 当前版本无成员：数据列表显示空状态，说明“请先完成切分/标注并构建数据集版本”。
- 数据登记但未归档：在数据集列表之外提供“待归入数据集”提示入口，避免数据消失。
- 版本切换后：清空当前选中的数据，重新加载成员列表，并更新面包屑上下文。
- 数据集或版本请求失败：保留现有 mock 展示，同时显示非阻塞错误提示。
- 删除操作沿用当前约束：本期不新增删除能力。

## 8. 验收标准

- 左侧不再出现独立“数据列表”导航。
- 点击数据中心默认进入数据集列表。
- 从数据集列表可进入数据集概览，再进入该数据集当前版本的数据列表。
- 数据列表展示的数据均属于当前数据集/版本，且含训练/验证/测试划分。
- 点击列表行可进入数据详情，并显示数据集归属。
- 面包屑可返回上一级，刷新后上下文不出现错乱。
- 切换数据集版本后列表、统计和面包屑同步更新。
- 数据集空版本、空成员、API 失败等状态均有明确提示。
- 既有核验、版本、分析、标注入口不被破坏。
- 前端构建、现有回归测试及后端测试通过。
