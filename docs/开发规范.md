## 1. 复用优先原则（必守）

**目标：凡有成熟、维护中的开源库可用的功能，一律复用，禁止重复造轮子；自己只写业务胶水与不可替代的定制逻辑。**

| 领域 | 复用组件 | 用途 | 手写范围 |
|---|---|---|---|
| 后端骨架 | FastAPI + SQLModel + pydantic-settings + Alembic | 应用、ORM、配置、迁移 | — |
| 分页 / DB 会话 | fastapi-sqla（支持 SQLModel + `page/page_size`）或 fastapi-pagination | 列表分页、session 依赖 | 统一信封 `{code,message,data}` 包装 |
| 认证 | PyJWT + pwdlib | JWT 签发/校验、bcrypt 哈希 | `login` / `me` / `get_current_user`（约 50 行） |
| 信号滤波 / PSD / STFT / 相图 / PDD | scipy.signal + numpy | 全部真实 DSP | 各 mode 薄封装 |
| DWT / 小波分解 / 小波能量 | PyWavelets（`pywt`） | 小波多层分量、时频特征 | 薄封装 |
| 时序统计特征 | scipy / numpy | 均值/方差/偏度/峰度/RMS/FFT 主频 | 约 30 行 |
| 视觉几何 / 纹理 | scikit-image（`regionprops` / `graycomatrix`） | 熔池面积/周长/圆形度、GLCM 纹理 | 薄封装 |
| 音频特征 | librosa（可选） | 频带能量/质心频率/过零率 | 薄封装 |
| 报告导出（PDF） | WeasyPrint + Jinja2（备选 xhtml2pdf） | 核验/分析/标注/特征/测试报告 | 报告 HTML 模板 |
| 异步任务调度 | 自研小型 DB 轮询执行器（可选 APScheduler 做调度） | `jobs` 表状态机执行 | 约 100 行（`jobs` 表已定制） |
| 日志轮转 | loguru | 接口调用日志的轮转/保留/脱敏 | 访问日志中间件（约 40 行） |
| 领域参考 | `weld-signal-classifier` 等开源项目 | 焊接信号统计特征与信号模拟的思路 | 只借鉴模式，不引入依赖 |

### 1.1 刻意不复用（评估后否决，不要擅自改回）

- **fastapi-users**：2026 起进入维护模式；强绑定自身路由与响应结构，与"最小登录 + 统一信封 + seed 管理员"契约冲突。改用 PyJWT + pwdlib 手写。
- **tsfresh**：自动抽取 750+ 特征，但依赖 pandas、性能开销大，前端仅展示指定的 8 类特征表，引入属过度设计。改用 scipy/pywt 直接实现。
- **通用任务队列**（quebec / fastapi-crons / supertask）：均假设自有任务表，与本项目 `jobs` + 每域任务表 1:1 的定制 schema 不符。写小型 DB 轮询执行器。
- **fastapi-pagination / fastapi-sqla 的分页响应**：其默认响应结构与本项目统一信封 `{code,message,data:{items,total,page,page_size}}` 冲突（库会包成独立的分页外壳）。已评估否决，改用自写 `paginate(items,total,page,page_size)` helper（`backend/app/schemas/common.py`），与信封体系天然一致。

### 1.2 新增依赖原则

- 新增第三方依赖前，先确认现有复用清单是否已能覆盖；能覆盖则不再引入。
- 需引入时，优先选活跃维护、使用广泛、协议宽松（MIT/Apache/BSD）的库。
- 所有复用库以正式依赖声明在 `backend/pyproject.toml`，不散装安装。

## 2. 接口调用轮转日志（必守）

所有 `/api/v1/*` 接口调用必须记录完整调用日志（轮转文件），供排障、审计与复盘。

### 2.1 实现方式

- 复用 **loguru**：`logger.add(API_LOG_DIR, rotation=..., retention=..., ...)` 配置式轮转，输出 `logs/api.log`，控制台同步一份。
- 新增一个 **ASGI 访问日志中间件**（`backend/app/core/logging.py`），覆盖全部 `/api/v1` 路由。

### 2.2 记录项

| 字段 | 来源 |
|---|---|
| 调用时间 / 耗时 | 中间件计时，ISO 8601（UTC）+ 耗时 ms |
| 调用人 | 从 JWT 解出 `username` / `display_name`；未登录记为 `anonymous` |
| 请求方法 / 路径 / query | 如 `POST /api/v1/welds?...` |
| 请求体 | JSON 完整记录；multipart/文件上传只记文件大小 |
| 返回状态码 / 返回体 | 完整 JSON；超长截断（默认 16 KB，可配） |
| 客户端 IP / correlation id | 便于串联请求 |

### 2.3 轮转与配置

配置写入 `backend/app/core/config.py` 与 `.env` / `.env.example`：

```
API_LOG_DIR=logs            # 日志目录（已 gitignore）
API_LOG_ROTATION=10 MB      # 按大小轮转；可改 "1 day" 按天
API_LOG_RETENTION=5         # 保留份数
```

### 2.4 脱敏（防密钥入日志）

- `password` / `token` / `secret` / `Authorization` 头一律替换为 `***`。
- `POST /auth/login` 请求体只记用户名，不记密码。
- 超大返回体按截断上限处理，避免日志膨胀。

### 2.5 与 `audit_logs` 的关系

- 轮转文件日志 = **全量接口访问日志**（调用现场）；
- `audit_logs` 表 = **业务级审计**（create/update/validate/export 等动作落库，见 `数据库设计.md` §3.23）。
- 两者互补，**都须实现**。

## 3. 实施边界与已确认决策

以下为需求评审确认的开发边界，编码时不得越界或擅自扩大范围：

1. **算法深度**：信号分析（滤波 / PSD / STFT / DWT / 小波 / 相图 / PDD）、特征提取（scipy / pywt / numpy / scikit-image）与**多模态对齐（已真实化：真实信号事件 + ffmpeg 视频探测/关键帧 + 真实产物 CSV/JPG/tracks.json，缺失模态部分成功转 unavailable）**为真实实现；模型训练、测试、推理、AI 预标注为**真实异步编排 + 模拟计算结果**（Job 状态、结果回填、MinIO 产物为真，计算内核为演示数据）。
2. **前端接线**：新建 `src/api/` + `hooks/`，逐页把 mock 数据源替换为 API 调用，**只改数据层、不动 UI 结构与信息架构**；不重写 `App.tsx`；新增最小登录页。
3. **部署**：当前**本地跑通、不部署**；Dockerfile/docker-compose 暂不实现；GitHub Pages workflow 保持不动（其静态版无后端支撑，属已知边界）。
4. **数据**：启动时自动 seed 管理员（用户名/密码从 `.env` 读）+ 与前端 mock 对齐的演示数据，保证页面非空可验收。
5. **契约基准**：接口以 `API接口清单.md` 为准（含已补全的 `raw-files`、`annotation-tasks` 等）；表结构以 `数据库设计.md` 为准（23 张表）；对象键以 `OSS存储设计.md` 为准。
6. **改动同步**：改动任何接口/表/对象键，须按 `docs/CLAUDE.md` 规则同步三份契约 + 两端代码。
7. **版本与模型生命周期**：数据版本由 `POST /welds/{id}/versions`、对齐任务成功、`POST /registrations` 产生；模型版本由训练任务成功自动产生、可经 `PATCH /models/{id}/versions/{vid}` 手动流转状态。本期**不支持删除**（标注/样本/数据集/模型/焊缝）。详见三份契约。
