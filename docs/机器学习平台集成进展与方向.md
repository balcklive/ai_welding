### 网络内网化：MinIO 服务端双端点（2026-09-05 落地并部署验证）

**背景/动机**：app/LS/mlflow 与 MinIO/MySQL 均在同一台服务器（`.remote` 记录 `182.61.59.135:8222`，wwwroot）；服务器 `.env` 原 `MINIO_ENDPOINT=182.61.59.135:8290`（公网端口映射），容器访问 MinIO 走公网 hairpin，吃 ~5-6Mbps 公网入口瓶颈（见 memory `deploy-server-upload-bandwidth`）。

**拓扑核实（SSH）**：
- MinIO/MySQL 为**同机宿主进程（非容器）**：MinIO `minio server --console :9001 /opt/data` 监听 `*:9000`；MySQL `mysqld` 仅监听 `127.0.0.1:3306`。`8290/8206` 是**云边缘 → 本机 9000/3306 的端口映射**（所以宿主 `ss` 看不到 8290/8206 监听）。
- 容器（aiwelding-net 网关 `172.18.0.1`）经 `172.18.0.1:9000` / `192.168.31.79:9000` 直连 MinIO = HTTP 200、1ms；MySQL 容器不可直连。

**落地（决策：双端点 · 只内网化 MinIO，MySQL 不动）**：
- 代码 commit `632e939`：`StorageClient` 拆 `_client`（数据面，`MINIO_SERVER_ENDPOINT` 内网，空回退公网）/ `_sign_client`（预签名，恒走公网 `MINIO_ENDPOINT`，交到浏览器的 URL）；`config` 加 `minio_server_endpoint`；`integrations/mlflow.py` 内嵌模式 S3 回退同步；`docker-compose.yml` 的 mlflow `MLFLOW_S3_ENDPOINT_URL=http://${MINIO_SERVER_ENDPOINT:-${MINIO_ENDPOINT}}`（嵌套默认已实测可用）。测试 `tests/test_storage.py` 增双端点单测。
- 服务器生效：`.env` 加 `MINIO_SERVER_ENDPOINT=172.18.0.1:9000`（备份 `.env.bak-internal-*`）；上传新 compose（备份 `docker-compose.yml.bak-*`）`docker compose up -d` 重建 mlflow；推 main commit `ac477bf` → CI run `33967636094` success，app 蓝绿切新镜像 `…:ac477bf…` healthy。

## 二、鉴权机制备忘（集成必读）

### Label Studio —— 必须"用户账号 + API key"
- **两类 key**（Account & Settings 生成，均绑定"某实例的某用户"）：
  - **Personal Access Token (PAT)** = JWT refresh 型，OSS 默认极长有效期；HTTP 直接调 REST 需先 `POST /api/token/refresh {refresh}` 换 ~5 分钟 `access`，用 `Authorization: Bearer <access>`；**配官方 `label-studio-sdk` 时设一次即可**（SDK 内部处理刷新）。
  - **Legacy Token** = 不轮换、长期，`Authorization: Token <token>` 直接用。
- PAT **只显示一次**，需即时安全保存；重新登录/再生成会拉黑旧 refresh。
- 主应用集成：`.env` 加 `LABEL_STUDIO_URL` + `LABEL_STUDIO_API_KEY`，SDK/REST 读取即可；**每个新部署的 LS 实例都要在该实例内重新生成 key**，不可跨实例复用；建议专用集成账号 + Legacy（或 PAT）并单独吊销。

### MLflow —— 默认无需鉴权；可选"用户账号+密码"，无 API key 概念
- **默认 Tracking Server 无鉴权**（谁能连上谁就能读写实验）。当前我们部署的 mlflow 即默认无鉴权，且宿主 8225 暴露公网 → **安全注意点**（见方向四）。
- **可选 basic-auth**：`mlflow server --app-name basic-auth` + `basic_auth.ini`（`default_permission`/`database_uri`/`admin_username`/`admin_password`）+ `MLFLOW_FLASK_SERVER_SECRET_KEY`；首次启用生成内置 `admin/password`。用户管理走 `/api/2.0/mlflow/users/*`（admin 才能建用户）——是**账号+密码**，不是"申请 API key"。客户端用 `MLFLOW_TRACKING_USERNAME`/`MLFLOW_TRACKING_PASSWORD` env。
- 主应用集成现在无需凭据（compose 内网 `mlflow:5000`）；多用户/外网暴露时再开 auth 或反代 OAuth。

## 三、后续方向（按序）

> 2026-09-05 评审后按里程碑计划重排为：**一期 = 轨道 A（LS 标注全链路，含前端 P1 并行）+ 轨道 B（MLflow 训练链）**；M3（数据集管理 P0，DM-02 已并入轨道 B）为二期、M4（能力吸收 UI 收敛）为长期触发项。里程碑/验收/待核实前提见 `superpowers/plans/2026-09-05-integrate-mlflow-labelstudio-into-main-app.md`。下方为要点速览。

1. **LS 标注集成适配层**（spec §3.3，最优先）：`backend/app/integrations/labelstudio.py` —— `uv add label-studio-sdk`；项目映射（源类型→项目 3/4/5）；`annotation_task`/锚点样本 → `tasks.create(data={image|csv: MinIO 预签名 URL})`；标注完成经 **webhook**（`annotation_created`/`updated`→FastAPI 回调）或 `tasks.list` 轮询 → LS region JSON 映射回 `annotations`（rectangle→box / brush|polygon→掩膜多边形 / timeseries range→segment `start|end`）→ `annotation_task` 完成 → 数据集构建/训练链路复用。best-effort（LS 不可达不炸 Job，参考 `integrations/mlflow.py`）。
2. **数据集管理 P0（批次 1）**：DM-02 训练把数据集快照摘要记 MLflow Run（+`model_versions.mlflow_run_id`）→ DM-03 构建质量扩展+分层划分 → DM-01 标签分布 UI。
3. **MLflow Phase 2**：真实焊接算法内核 + `log_model`/`register_model`（边界在 `torch_training.py` 保持 `CpuTrainingResult` 契约）；内核上线或多人看 UI 时评估 basic-auth。
4. **安全收敛**：LS 的 8224 与 MLflow 的 8225 现为公网无鉴权 —— 近期在云安全组收紧为办公室/内网 IP 白名单（或改宿主绑定 127.0.0.1 + SSH 隧道），MLflow 若要多人访问再开 basic-auth；LS 建专用集成账号 + 轮换已暴露的 PAT。
5. **长期吸收**：把标注工作流与实验/模型 UI 吸收入主应用（引擎与数据模型复用本方案），外部 LS/MLflow 服务逐步转为可选后端引擎。

## 四、风险与注意
- LS/MLflow 后端现为 **SQLite 落卷**（阶段子系统）；规模上来或做"吸收"时再评估迁 MySQL/Postgres。
- LS 网页首个注册用户即管理员；标注员账号由管理员在 LS 内创建。
- 改动任何接口/契约仍须同步 `docs/` 三份契约 + 涉及目录 CLAUDE.md。
