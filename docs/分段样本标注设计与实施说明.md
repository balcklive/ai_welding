# 分段样本标注（段级分类）设计与实施说明

> 一期实施日期：2026-09-22。上游：`docs/多模态时间统一样本分段重构设计方案.md` 产出的
> v3 多模态样本（一个 `Sample` = 秒级时间窗 + 样本包）。
> 契约：`docs/API接口清单.md` §3.9；表结构：`docs/数据库设计.md` §3.27。

## 1. 范围与不做什么

一期只回答一个问题：**这一段（时间窗）整体是正常还是缺陷？**

- 每个 v3 `Sample` 只有**一个主结论**：`normal`（正常）或 `defect`（缺陷 + 一个主缺陷类别）。
- **不做**框、点、掩膜，**不做**两级精度（如"缺陷区段 + 缺陷内的框"）。
- **不做**"可疑/待复核"业务标签。`review_status` 列已按可空 + 默认 `approved` 预留，
  一期 UI 不暴露该流程——将来加复核态不必改表。
- **不改动**旧的几何标注线：`annotations`（box/segment/polygon）与 `POST …/labels` 原样保留，
  两条线互不读写。既有 `label_categories`（模型口径 6 类）也原样保留。

## 2. 数据模型

### 2.1 `sample_annotations`（新表，迁移 `0020`）

| 列 | 说明 |
|---|---|
| `sample_id` | **UK**。一个 v3 样本至多一行——upsert 语义天然成立 |
| `label` | `normal` / `defect` |
| `defect_category_id` | 主缺陷类别，FK → `option_items.id`（见 §3 词表）。`label=normal` 时为 NULL |
| `defect_category_name` | **写入当时**的类别名快照 |
| `note` | 备注（≤512，纯空白归一为空） |
| `schema_version` | 标注数据 schema 版本，当前 `1`（`services/sample_annotation.SCHEMA_VERSION`） |
| `review_status` | 预留（默认 `approved`） |
| `annotator` / `annotator_id` | 展示名 + 稳定用户 id |
| `created_at` / `updated_at` | |

**为什么存名称快照**：类别可以被管理员改名/停用（历史台账必须还能读），而数据集快照与训练输入
是不可复现的冻结产物。存名字快照 = 标注行自解释，不依赖词表当时的形态。这与
`annotations.category` 存字符串是同一个取舍。

**为什么 `schema_version` 是列而不是常量**：数据集构建 / 离线导出是**异步、跨版本**的消费方——
今天写进 `dataset_items.annotations` 的快照，半年后可能被另一版代码读。消费前先认版本号，
才能安全地演进结构（见 §5）。

### 2.2 与 `dataset_items.annotations` 的关系

构建数据集时，两条标注线**合并**写进冻结快照（`services/datasets.py::_annotation_snapshots`）：

```jsonc
[
  {"category": "焊瘤", "confidence": null, "kind": "box"},              // 旧几何标注，原样
  {"category": "气孔", "confidence": null, "kind": "segment_class",     // 段级标注
   "label": "defect"}
]
```

训练侧（`torch_training.load_real_examples`）**优先认 `label`**，认不到才按 `DEFECT_LABELS`
白名单折叠类别名。这样管理员在词表里加一个自定义类别（名字不在白名单里）也不会把结论折反
——这是"词表可管理"与"训练标签正确"能同时成立的前提。

同时 `_compute_quality` 的 `empty_label_rate`（未标注切片占比）必须用**合并后**的口径，
否则快照里明明有结论的切片会被记成"空标注"。

## 3. 词表管理与兼容策略

### 3.1 为什么是新的一组，而不是改 `label_categories`

既有 `label_categories`（焊瘤/气孔/未熔合/咬边/正常/熔池）是**模型口径**，被 LS 集成
（项目 3/4/5 映射）与 `POST …/annotation-tasks/{id}/samples/{id}/labels` 的类别校验依赖。
本期要求的词表（气孔/未焊透/焊穿/咬边/裂纹/成形不良/其他）是**段级分类口径**，两者不重合
（"正常"在旧表里是一个类别，在新口径里是 `label` 而不是类别）。把旧表改掉会同时破坏 LS 集成、
旧标注校验与历史数据展示。

### 3.2 存储：复用 `option_items` 的第 7 个分组

`defect_category` 落在既有 `option_items` 表（`group_key='defect_category'`），**不新建表、
不新建服务**——直接复用「系统设置 → 可选项字典」那套：`(group_key,value)` 唯一、
`active` 软删、`sort_order` 排序、`move` 整组重排。前端设置页按后端返回的分组数组渲染，
新增一组即自动出现在页面，无需前端改动。

唯一需要单独处理的是**引用统计**：其它分组按字符串列统计（`data_records.machine` 等），
本组按**外键 id** 统计（`sample_annotations.defect_category_id`）。因此
`services/settings.py::reference_count` 收的是**行对象**而不是值。

### 3.3 删除 / 停用 / 改名语义

| 操作 | 行为 |
|---|---|
| 删除**未被引用**的类别 | 物理删除 |
| 删除**已被引用**的类别 | 降级为**停用**（`active=false`），返回 `mode="deactivated"` |
| 停用类别 | 不出现在新标注的候选里；**历史标注仍按行内快照显示名称** |
| 改名 | 只影响后续写入；历史标注的名称快照不回填 |
| 编辑一条**本来就引用了停用类别**的旧标注 | **放行**（否则类别一停用，那条历史标注就永远改不动了） |

## 4. 工作流（前端）

入口：侧边栏「分析与标注 → 分段样本标注」（路由 `analysis/sample-annotation`）；
也可在「样本分段」页生成成功后点「去标注这批样本」直达。

```
选择焊缝（全局上下文）
  └─ 可标注分段任务列表（已完成 + v3，带进度）   GET /welds/{id}/segment-annotation-tasks
       └─ 工作台
            ├─ 全局条（整条焊缝一窗一格；色块看进度与缺陷分布，点击跳批）
            ├─ 批次时间轴（20 窗横铺，每格 ~65px）—— 统一横轴，窗口竖线贯穿全部泳道
            │    · 时序  —— 四条信号泳道（服务端降采样轨道，按批次裁切）
            │    · 焊缝图片 —— 每格是本段自己的 ROI 投影切片
            │    · 视频帧 —— 每格是本段自己的代表帧
            │    · 标注行 —— 勾 / 叉 + 类别，结论直接落在窗口列上（不依赖任何模态）
            └─ 右栏：结论表单（正常 / 缺陷 + 类别 / 备注）+ 本窗三模态细节
                 · 时序  —— 该窗内的局部波形（服务端已降采样）
                 · 视频  —— seek 到本窗起点：t_video = t_signal − offset
                 · 焊缝图片 —— 按弧长投影裁出的本窗条带
```

三条硬约束：

1. **三模态共用一个窗**：窗口起止只来自该 `Sample` 的 `start_time`/`end_time`（服务端切分时
   定下）。前端不提供任何按模态独立标注或独立时间轴的操作——"各轨各自标注"的歧义正是本期
   要避免的。
2. **模态缺失不阻断标注**：未标定、无视频、图片裁切失败都只显示原因，结论表单照常可用。
   缺陷结论来自人工判断，不该因为某个增强模态缺失而无法录入。
3. **不在前端算窗口**：窗口集合、起止、边界一律来自服务端（`GET …/annotation-timeline`，
   它读的是**已落库的 `Sample`**，与分段任务切出来的是同一批）。前端只做批次的切片与
   坐标换算（批次内 `x = t − batchFrom`），不复制任何切分算术。

> **2026-09-23 修订：硬约束 3 原来是"不缓存全量切片"（样本列表每页 50、翻页自动带过）。**
> 改成总览打标流后，"一屏看到整条焊缝"与"每页只拿 50 条"直接冲突，故口径细化为
> **全量的是索引，不是媒体**：
> - **索引全量**——窗口的 `sample_id`/起止/标注态/短名由 `annotation-timeline` 一次给全。
>   几百段的元信息只有几十 KB，分页拉反而是纯粹的摩擦（旧稿要手动合并两份分页、靠保存前的
>   下标兜圈子才能"保存并下一段"）。
> - **媒体按批**——每段的视频帧与焊缝切片只是**短期预签名 URL**（服务端不传字节）；
>   前端**只给当前批次的 20 个窗口挂 `<img loading="lazy">`**，批次之外不渲染任何切片。
> - 批次横铺（20 段/屏）而不是一屏铺满：一条焊缝 90~200 段，全铺时每格只有十几像素、
>   看不见帧图，总览就退化成一排色块了。全局条负责"看整体"，批次负责"看清并打标"。

## 5. 数据集构建消费

- **在线**：`GET /split-tasks/{task_id}/annotation-export` 返回顶层带 `schema_version` 的
  完整标注（未标注样本也在，`label=null`——"没标"本身是有信息的）。
- **构建时**：`_annotation_snapshots` 合并两条标注线写进 `dataset_items.annotations`（冻结），
  训练只读快照，不受"构建后改标注"影响（与 T16.1 的冻结语义一致）。
- **消费约定**：先认 `schema_version`；段级条目认 `kind="segment_class"` + `label`，
  **不要**只看 `category` 字符串。

## 6. 迁移与兼容

- 迁移 `0020`：新建 `sample_annotations` + 幂等插入 7 条出厂词表项。
- **纯 expand**：老代码不读新表，新代码不依赖老数据的回填；无历史行需要转换。
- 旧几何标注（`annotations`）、旧词表（`label_categories`）、旧切分任务（`rules_version<=2`）
  一律不受影响；段级标注对非 v3/未完成的分段任务**主动拒绝**（400），而不是尽力尝试。
- 回滚：`downgrade` **先删表再删词表项**——反过来会被
  `sample_annotations.defect_category_id` 的外键拦下。管理员自己加的类别不会被回滚删掉。

## 7. 已实施 / 未覆盖

**已实施**：模型 + 迁移 `0020`、服务层、7 个端点、段级词表分组、前端工作台 + 路由 + 设置页
（自动生效）、数据集构建消费 + 训练标签折叠、后端 16 个用例（含真实 HTTP + 真实 Job 执行器
的构建链路）+ 前端静态回归 9 条。

**未覆盖（已知，按需再排期）**：

1. **复核流程**：`review_status` 只有列与默认值，没有流转接口，也没有"待复核"筛选。
2. **归属 ACL 的彻底统一**：本期新端点沿用分段域的 owner 口径；**旧的**
   `analysis_annotations.py` 那条标注线仍没有 owner 校验（既存问题，未在本期改动）。
3. **多人协同 / 并发写**：一个样本一行 + upsert，最后写入者覆盖；没有乐观锁或
   "标注员 A/B 交叉校验"。
4. **批量操作**：没有"整页快速标正常"、导出前校验等效率工具。
5. **LS 集成**：段级分类未接 Label Studio，仍走主应用自研画布。
6. **构建前的覆盖率闸门**：数据集构建不因"还有大量未标注"而拦截（`empty_label_rate` 只作为
   质量指标暴露）。
