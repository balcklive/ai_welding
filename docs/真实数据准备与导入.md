# 真实数据准备与导入说明

> 适用对象：需要把**真实生产数据**（焊接视频、时序信号、音频、图像）导入本平台的工艺/数据工程师。
> 依据契约：`docs/API接口清单.md`、`docs/数据库设计.md`、`docs/OSS存储设计.md`、`docs/开发规范.md`。
> 结论先说：**本项目已完成真实数据导入、起收弧识别和报告链路验证；按本文档准备文件并走登记/上传/挂载流程即可入库可查。** 演示数据仍用于初始化验收环境，真实能力边界和部分算法模拟限制见 §6，务必先读。

---

## 1. 数据全貌（什么数据、存在哪）

系统数据分两层：

| 层 | 载体 | 内容 |
|---|---|---|
| 元数据 | MySQL `ai_welding` | 焊缝信息（`data_records`）、版本链（`data_versions`）、核验/标注/数据集/模型等业务表 |
| 原始文件 | MinIO 桶 `aiwelding` | 视频/时序/音频/图像等**多模态大文件**，DB 只存 `object_key` |

**数据生命周期**：登记（建焊缝 + v1.0 原始版本）→ 挂载原始文件 → 版本链（去噪/人工修正/时间对齐）→ 核验 → 切分/标注 → 构建数据集 → 训练/测试/推理。

## 2. 需要准备的数据清单（按模态）

### 2.1 焊缝元数据（每批必配）
对应 `POST /registrations` 请求体（`source` 必填，其余可空）：

| 字段 | 类型 | 必填 | 示例 | 说明 |
|---|---|---|---|---|
| `dataset_id` | int | ✅ | `1` | 归属数据集（`GET /datasets` 取 id；登记必须归属，缺失 → 422，指向不存在 → 40401） |
| `source` | string | ✅ | `产线相机 · 03号` | 采集来源/产线位，决定列表筛选项 |
| `collected_at` | datetime | | `2026-08-15T09:42:00Z` | 采集时间（ISO 8601 UTC） |
| `weld_name` | string | | `MAG 短路过渡 · 典型稳定样本` | 展示名 |
| `product` | string | | `车体侧梁 · A 型试件` | 工件/产品 |
| `machine` | string | | `Fronius CMT` | 焊机品牌+型号（列表按品牌筛选，取前缀） |
| `weld_method` | string | | `MAG焊` / `MIG焊` / `TIG焊` | 焊接方法 |
| `material` | string | | `Q235B` | 母材 |
| `thickness` | string | | `6 mm` | 板厚 |
| `current_voltage` | string | | `180 A / 22 V` | 电流/电压 |
| `sample_rate` | string | | `10 kHz` | 采样率 |

系统自动生成业务号：`weld_id = WLD-YYYYMMDD-序号`、`registration_no = REG-YYYYMMDD-序号`，无需自备。

### 2.2 焊接视频
| 项 | 要求 |
|---|---|
| 格式 | **MP4 / H.264**（浏览器 `<video>` 播放兼容；播放走 MinIO 预签名 URL，支持 Range 拖动） |
| 建议 | 分辨率 ≥ 720p，帧率 ≥ 25fps，时长 ≥ 5s（与演示数据 5.42s 对齐） |
| 命名 | `0001.mp4`、`0002.mp4`…（同一条焊缝多视角可递增） |
| 对象键 | `raw/{REG号}/0001.mp4` |

### 2.3 时序信号 CSV
| 项 | 要求 |
|---|---|
| 格式 | UTF-8 无 BOM，首行表头，逗号分隔 |
| 列 | 至少含**时间** + 一个通道；建议 `时间,电流(A),电压(V),气体流量(L/min),送丝速度(m/min)` |
| 建议 | 采样率 ≥ 1000Hz，时长 ≥ 5s |
| 命名 | `timeseries.csv` |
| 对象键 | `raw/{REG号}/timeseries.csv` |
| 处理 | 挂载后**自动导入**：解析 + 10 条格式/类型校验（列名/数值/量程/采样一致性/空值/重复时间戳）→ 通过则写 MinIO Parquet（`processed/{weld_id}/signals/{id}.parquet`）并供分析读取；失败则记录校验结论，分析回退生成信号 |

> ⚠️ **实测注意事项（真实数据导入已跑通，2026-08）**：
> 1. **`time` 列支持 ISO 8601 时间戳与相对数值秒**——采样率由相邻时间差推导（R6）。ISO 字符串（如 `2026-06-17T14:22:23.000164Z`，支持微秒步进）经 `_time_column_to_seconds` 自动转相对秒（2026-08-28 修复，`test_signal_ingest_iso_time.py` 回归）；相对数值秒（首条置 0，`(t-t0).total_seconds()`）亦可。若时间列两种都解析不出，R6「采样一致性」fail → 导入失败。
> 2. **量程已按真实焊接范围放宽**：`CHANNEL_SPECS` 电流 0–600A / 电压 0–80V / 气体 0–60 L/min / 送丝 0–20 m/min（`backend/app/services/signals.py`）。MAG 短路过渡实测电流峰值 ~530A、电压峰值 ~70V，原演示档 0–300A/0–40V 会触发 R5「量程」fail。
> 3. 列名未识别不致命（如 `tag0`/`tag1`）——仅 R2 表头识别 warn，overall=warn 仍会写 Parquet 供分析；但该列**不会被导入为通道**（缺失通道在 Parquet 中补零）。已支持的表头别名见 `signal_ingest._HEADER_ALIASES`：气体流量列名 `GasSpeed`/`gas_speed`/`gasflow`/`gas_flow`/`气体流量` 等均可映射到 gas 通道（2026-08-29 补入 `GasSpeed` 系列，此前该列会被当未知列丢弃、gas 补零）；仍不认识的列名要么改写为别名表内的名字，要么补进 `_HEADER_ALIASES` 对应通道。

### 2.4 焊接音频
| 项 | 要求 |

| ⚠️ | 同上，音频特征当前由程序生成，不读此文件 |

### 2.5 图像 / 红外（可选）

## 3. 对象键约定（文件放哪）

单桶 `aiwelding` + 前缀体系（`docs/OSS存储设计.md` §2）：

```
aiwelding/
├── raw/{registration_no}/{filename}      # 原始数据（登记挂载，版本链 v1.0）
├── processed/{weld_id}/…                 # 对齐/切分中间产物（任务生成）
├── models/{model_version_id}/weights.pt  # 模型权重（训练模拟生成）
├── reports/{report_type}/{ref_id}.pdf    # 导出报告
└── uploads/{uuid}/{filename}             # 临时上传区（推理输入等，30 天清理）
```

文件名须规范化：小写、空格→`_`、去特殊字符、≤255（上传端 `normalize_key` 自动处理）。

## 4. 导入流程

### 4.1 界面手动（熟悉 UI / 少量数据）
1. 浏览器打开 `http://<host>:5173/ai_welding/`，登录 `admin`。
2. 数据管理 → 列表页 → **先选择一条数据**（"先选数据，再处理数据"上下文模式）→ 右上角"**登记数据**"→ 进入登记页。
3. 填登记表单 → 提交 → 得到自动生成的 `REG-…`。
4. 上传文件（<100MB 走代理上传，≥100MB 走预签名直传）→ 自动挂载到 v1.0 版本。

### 4.2 API 脚本（批量导入，推荐）
完整调用序列（curl 示意，token 为登录返回的 `access_token`）：

```bash
BASE=http://localhost:8000/api/v1

# 1) 登录拿 token
TOKEN=$(curl -s -X POST $BASE/auth/login -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"<ADMIN_PASSWORD>"}' \
  | python3 -c "import sys,json;print(json.load(sys.stdin)['data']['access_token'])")

# 2) 登记（dataset_id 与 source 必填）→ 返回 record_payload，含 weld_id / registration_no / id
#    dataset_id 用 GET /datasets 返回的 id（如 1 = 焊接缺陷检测集）
REG=$(curl -s -X POST $BASE/registrations -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"dataset_id":1,"source":"产线相机 · 03号","collected_at":"2026-08-15T09:42:00Z",
       "weld_name":"真实样本 A","machine":"Fronius CMT","weld_method":"MAG焊",
       "material":"Q235B","thickness":"6 mm","sample_rate":"10 kHz"}')
#   取出 REG-… / 数字 id（按响应 data.registration_no / data.id）

# 3) 上传原始文件 → 拿到 object_key
#    小文件：POST /files/upload（multipart file）；对象键在 uploads/{uuid}/ 下
#    推荐（落 raw/ 前缀，符合 OSS 约定）：POST /files/presign-upload
curl -s -X POST $BASE/files/presign-upload -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"filename":"0001.mp4","size":<字节数>,"content_type":"video/mp4","prefix":"raw/REG-20260815-00001"}'
#   → {object_key:"raw/REG-…/0001.mp4", upload_url:"…"}，再用 upload_url 发 PUT 直传文件
#   大视频（≥100MB）必须走 presign-upload；小文件也可走它。

# 4) 挂载到 v1.0 版本（去重追加 object_keys + 累加 storage_bytes）
curl -s -X POST $BASE/registrations/<REG号>/raw-files -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"object_keys":["raw/REG-…/0001.mp4","raw/REG-…/timeseries.csv"],
       "storage_bytes":<总字节数>}'

# 5)（可选）后续加版本：去噪/人工修正
curl -s -X POST $BASE/welds/<WLD号>/versions -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"action":"去噪处理","note":"xx","object_keys":["processed/WLD-…/denoise/timeseries.csv"]}'
```

> 说明：
> - `POST /files/upload`（<100MB）对象键固定落在 `uploads/{uuid}/` 临时区；若要让原始文件落 `raw/` 前缀，一律用 `POST /files/presign-upload`（对 size 无下限，仅限 `0 < size ≤ 2GB`）。
> - `POST /registrations/{id}/raw-files` 的 `{id}` 传 `REG-…` 或 `WLD-…` 均可（按业务号解析）。
> - 大批量建议写一次性导入脚本：读清单 → 循环登记/上传/挂载，异常打日志、幂等可重跑（业务号按日期+当日序号生成，重复登记会得到新序号）。

## 5. 数据与现有演示数据的切换

- 演示数据是 `app/core/seed.py` 启动时幂等 seed 的（4 条焊缝/3 模型/5 标注类别…）。
- 想清掉演示数据、只留真实数据：删 `data_records` 等业务表行（保留 `users`/`label_categories` 等基础表），或换一个空库 + 不跑 seed_demo（改 `seed.py`）。**无 DELETE 端点**，需直接 SQL 或写一次性清理脚本。
- 生产部署建议：新库 + `SECRET_KEY`/`ADMIN_PASSWORD` 改为强值后，再按 §4 导入真实数据。

## 6. 架构限制与期望管理（务必先读）

1. **DSP 分析优先读真实信号（Task 18 已实现）。** 挂载 `.csv` 后自动触发 `signal_ingest` 任务：解析 + 10 条格式/类型校验（列名映射、数值类型、量程、采样一致性、空值、重复时间戳），通过则写 MinIO Parquet（`processed/{weld_id}/signals/{id}.parquet`），分析页波形/PSD/STFT/特征/稳定度改读真实信号（响应 `source="real"`）；**无成功导入时回退确定性生成**（`source="generated"`，兼容旧记录/校验失败）。CSV 表头支持中英文别名（时间/时间戳、电流/current、电压/voltage、气体流量/gas、送丝速度/wire）。events/anomalies（起弧/焊接段/异常区段）由启发式阈值检测（确定性），结果页标记来源。
2. **多模态对齐已真实化；切分/训练/测试/推理的部分算法结果仍是模拟的。** 对齐使用真实视频探测、真实信号事件并生成真实产物；切分、训练、测试、推理的 Job 编排、DB 记录、MinIO 产物是真实的，但部分业务结果（例如损失曲线、混淆矩阵、检测框）仍为程序生成的演示值；`weights.pt` 是训练模拟生成的占位权重，不是真实训练模型。标注的任务、样本、保存和导出链路按真实系统验收。
3. **标注页样本图为前端静态图。** `Annotation` 组件当前用打包的静态图片，不走 MinIO 真实帧；"图片预览"依赖 `getFileUrl`，对象存在才可显示。
