# 功能验证测试清单

> 适用范围：焊接数据智能分析与 AI 建模平台
>
> 本清单用于在真实 CSV、图片、视频数据已经完成“登记 → 上传 → 文件挂载 → 信号导入 → 数据核验 → 检测/分析”验证后，继续验证平台剩余业务流程、接口状态、数据关联、文件产物和异常处理。
>
> 更新日期：2026-08-25

## 1. 测试说明

### 1.1 当前已验证范围

以下链路已有真实数据端到端记录，详见 [`真实数据端到端走通记录.md`](./真实数据端到端走通记录.md)：

```text
登录
  → 数据登记
  → CSV / 图片 / 视频上传
  → 原始文件挂载
  → CSV 信号导入
  → 数据核验
  → 真实信号时域 / PSD / STFT 分析
  → 异常检测
  → 特征提取
  → 分析报告导出
```

### 1.2 测试环境

- 后端：`cd backend && uv run uvicorn app.main:app --reload`
- 前端：`npm run dev`
- 健康检查：`GET /api/v1/health`
- 测试账号：使用根目录 `.env` 中的 `ADMIN_USERNAME` / `ADMIN_PASSWORD`
- 真实数据：使用 `docs/真实数据准备与导入.md` 中的样本
- 破坏性数据：使用 `backend/tests/fixtures/destructive/`，不得用于生产库
- 取证位置：`backend/logs/api.log`、MySQL 业务表、MinIO `aiwelding` 桶

### 1.3 测试记录规则

每一项至少记录：

- 测试编号、执行时间、执行人
- 使用的焊缝 ID、数据版本、数据集版本或模型版本
- 操作步骤和实际结果
- 预期结果与是否通过
- API 请求/响应、Job ID、报告 URL 或 MinIO object key
- 页面截图或日志位置
- 失败时记录复现步骤、错误码和影响范围

状态建议使用：`未执行`、`通过`、`失败`、`阻塞`、`不适用`。

## 6. P2：破坏性、边界和负载测试

执行前必须使用隔离数据库、隔离 MinIO 桶或完成备份。详细流程见 [`破坏性测试指导.md`](./破坏性测试指导.md)。

### 6.1 输入和文件边界

- [ ] **BOUNDARY-001** 搜索框输入 `' OR 1=1--`、`'; DROP TABLE users;--`。
- [ ] **BOUNDARY-002** 输入 `<script>alert(1)</script>` 和 `<img onerror=alert(1)>`，确认无 XSS。
- [ ] **BOUNDARY-003** 上传 0 字节文件。
- [ ] **BOUNDARY-004** 上传空 CSV、无表头 CSV、非数值 CSV、超量程 CSV。
- [ ] **BOUNDARY-005** 上传 BOM、UTF-16、坏行、列数不一致和超长行 CSV。
- [ ] **BOUNDARY-006** 上传损坏 MP4、损坏 JPG、空 WAV。
- [ ] **BOUNDARY-007** 上传伪造扩展名文件、超长文件名和路径穿越文件名。
- [ ] **BOUNDARY-008** 上传大 CSV、超大图片和超过单文件限制的文件。
- [ ] **BOUNDARY-009** 手改 `page`、`page_size`、分析 mode/channel/filter 参数。

### 6.2 并发和负载

- [ ] **LOAD-001** 并发重复提交登记，确认唯一约束返回 409 而不是 500。
- [ ] **LOAD-002** 并发挂载同一 CSV，确认不会重复导入或产生重复任务。
- [ ] **LOAD-003** 同时触发多个导入、对齐、训练或推理任务，确认 Job 执行器不死锁。
- [ ] **LOAD-004** 使用 50–200 个并发请求访问总览和数据列表，观察响应时间、连接池和错误率。
- [ ] **LOAD-005** 大 CSV 导入期间同时访问分析页面，确认不会互相拖死。
- [ ] **LOAD-006** 任务运行期间刷新、退出再进入页面，确认任务结果最终可恢复。

**判定标准：** 浏览器不白屏；预期错误返回正确 4xx；无未处理 500；无异常数据膨胀；数据库和 MinIO 只产生预期对象。

## 7. 建议的完整验收场景

使用一条真实焊缝按以下顺序执行：

```text
真实数据导入
  → 查看版本链
  → 多模态对齐
  → 生成切分样本
  → 创建并保存标注
  → 执行特征提取
  → 创建数据集
  → 创建固定数据集版本
  → 查看适配检查和数据血缘
  → 启动模型训练
  → 模型测试
  → 上传图片/视频进行推理
  → 导出分析、测试和特征报告
  → 核对数据库、MinIO 和审计日志
```

该场景全部通过后，再执行破坏性、并发和故障恢复测试。

## 8. 当前实现边界

- 真实 CSV 信号已接入解析、校验、Parquet 存储和 DSP 分析。
- 对齐、切分、标注任务的部分业务结果目前为模拟或静态回退，不能作为算法精度验收。
- 训练、测试、推理的指标、曲线、混淆矩阵和模型权重目前为模拟结果，不能替代真实模型验收。
- 标注页样本图存在静态图片回退；真实文件存在性需要单独验证。
- 登录目前需要重点关注弱默认密码、暴力尝试和细粒度权限边界。
- 破坏性测试会污染数据，必须在隔离或已备份环境中执行。
