# 多模态时间统一样本分段重构设计方案

> 状态：设计提案，待实施  
> 日期：2026-09-22（2026-09-22 修订：引入统一坐标映射，对齐层与切分层职责重划）  
> 范围：`分析 → 对齐` 的标定与坐标映射，`分析 → 样本分段` 的规则、预览、产物、接口和后续消费链路

## 1. 背景与问题

现有分段功能同时保留“按帧/按秒”的规则入口，并按“目标检测/时序分类”二选一生成产物：前者只抽窗口中点视频帧，后者只写窗口信号 CSV。它导致以下问题：

1. 切分规则不唯一：帧、采样点、秒混在同一概念中，用户难以判断实际时间范围。
2. 切片不是多模态对象：同一个样本不能同时追溯时序、视频和图片。
3. 预览不可核验：当前仅有概览色带/单一波形，不能确认不同模态是否落入同一时间窗。
4. 预览与执行虽然共享部分窗口算法，但预览返回的信息不足；用户无法在创建任务前审查将要生成的样本内容。
5. “输出任务格式”过早决定了数据产物，阻断同一批切片复用于检测、分类、分割等后续任务。

本方案将其重构为**时间统一的多模态样本分段**：秒是唯一切分单位，视频帧率、信号采样率和焊缝图片长度只用于把同一个时间窗映射到各模态资源。

### 1.1 关键发现：对齐任务声称对齐，但从未建立坐标映射

排查现有实现（`backend/app/services/alignment.py`）后确认：**对齐任务真实执行了事件检测、视频探测与关键帧抽取、产物上传，但没有做任何跨模态坐标换算。**

| 轨道 | 现状 | 问题 |
|---|---|---|
| timeseries | `aligned=True`，metadata 为 `sample_rate/duration/channels` | 它是基准轴本身，`True` 成立 |
| video | `aligned=True`（`alignment.py:424`），metadata 为 `duration/fps/width/height/keyframes` | **metadata 全是视频自身固有属性，没有一个字段描述它与信号时间轴的关系**。`aligned=True` 是声明，不是计算。 |
| audio / infrared | `aligned=False`（`alignment.py:446,457`），reason「对齐内核未启用，仅登记元数据」 | 焊缝图片被归入此桶，并被判定「无连续时间轴」——**它有轴，只是轴是长度不是时间** |

全后端 `offset` / `time_offset` / `sync` 搜索无任何跨模态时间换算命中。下游三处因此各自“假装” `t_video ≡ t_signal`：

| 位置 | 代码 | 后果 |
|---|---|---|
| `services/alignment.py:114` → `media_probe.py:195` | `ffmpeg -ss {信号事件秒}` | 关键帧抽错时刻 |
| `jobs/split.py:98` | `video_frame_no = 窗口中点秒 × fps` | 帧号对不上真实帧 |
| `src/features/alignment/AlignmentWorkspace.tsx:273-282` | `video.currentTime = 信号秒` | 播放器 seek 错位 |

**真实数据实测**（`data/data/SP2026-06-000201/`）：

```text
信号 SP2026-06-000201.csv : 910,000 行 @5000Hz
     2026-06-17T14:22:23.000164Z → 14:25:24.999964Z   span = 182.0 s
视频 SP2026-06-000201.MP4 : 30fps, duration = 180.9 s
                                  差 1.1 s
```

两个可用 MP4（含演示用的 `113-1410420e.mp4`）**均无 `creation_time` 容器标签**，视频文件里没有留下录制墙上时钟。因此 1.1 s 的时长差只能给出偏移量的**上界**，不能确定偏移本身。在 2 秒窗口下，1.1 s 相当于窗口宽度的 55%，视频关键帧完全可能落在窗口之外——而这一切是静默发生的。

此外，`services/welds.py:1067-1070` 的核验规则「多模态时间戳对齐」实现为：

```python
if has_files:
    rules.append(passed("多模态时间戳对齐"))   # 挂了任意文件就判通过
```

从未比对过任何时间戳。系统在缺少对齐依据的情况下主动报告核验通过。

**结论**：对齐是坐标统一的正确归属地，骨架（per-modality 的 `aligned`/`availability`/`reason` 字段）已在，缺的是把映射算出来。本方案的核心补充即在于此。

## 2. 目标、非目标与决策

### 2.1 目标

- **对齐层建立统一坐标系**：把时序时间、视频时间、焊缝图片长度接到同一根基准轴上，产出一份可执行的映射，而非布尔声明。
- 按固定时间间隔生成样本窗口，默认“时长 2 秒、步长 2 秒”。
- 允许用户实时调整时长、步长、有效事件边界；每次调整均更新预测数量和多模态预览，**不创建任务、不写入任何产物**。
- 在同一条时间坐标上预览时序数据、视频、焊缝图片，并在所有轨道使用完全相同的样本边界。
- 每个最终样本包含统一的时间范围及每一种可用模态的引用与映射信息。
- 预览和正式生成必须复用同一个服务端窗口算法，保证边界、数量和尾片处理完全一致。
- 支持模态缺失：缺少视频、图片或音频不阻止存在真实时序信号的分段；界面和 manifest 必须如实标记缺失。

### 2.2 非目标

- 本次不改变起收弧/有效焊接事件的识别算法，仅消费其边界并允许人工修正。
- 本次不改变焊缝图片的 ROI 框选与视频零点标定的**人工**性质；不实现自动配准算法。
- 本次不在预览阶段批量生成短视频文件、复制全部图片或导出完整切片 CSV。
- 本次不定义训练模型的输入组合；训练、标注在后续工作流中从样本包选择所需模态。
- 本次不要求所有历史 `SplitTask` 迁移为新样本；历史记录只读保留。
- 本次不引入像素标定（像素↔毫米换算）。焊缝图片的空间映射以**比例**表达，不需要物理标尺。

### 2.3 已确认决策

| 决策 | 口径 |
|---|---|
| 唯一切分单位 | 秒（`second`）；移除前端“按帧切分”入口。 |
| 默认时长 | `2.0 秒`。 |
| 默认步长 | `2.0 秒`，即默认不重叠。 |
| 调整方式 | 数字输入，允许 0.1 秒精度；可选常用快捷值。输入合法且停顿 300 ms 后实时请求预览。 |
| 重叠 | `步长 < 时长` 即重叠；明确展示重叠秒数与比例。 |
| 尾片 | 默认 `drop`：不足一个完整时长的末尾窗口不生成；可选 `keep`（保留不等长尾片）仅在后续业务确认后开放。 |
| 有效区间 | 默认使用系统检测的焊接事件边界；可拖动起止时间人工修正。可选缓冲秒数作用于事件边界后再分段。 |
| 视频切片 | 样本首先保存视频时间范围与关键帧引用；不默认物理裁切 MP4。 |
| **焊缝图片的定义** | **不是**“按时间连续采集的图片”（那是视频）。焊缝图片是焊缝宏观照片，其轴是**沿焊缝的长度**，属空间模态。 |
| **焊缝图片定位** | 人工在照片上框选轴对齐矩形 ROI 包住焊缝条带；系统沿 ROI 长边按比例切分。不使用自动分割算法。 |
| **焊缝图片切分段数** | **不由图片独立决定**，而是时间窗边界经坐标映射反投影到像素后的结果。切分段数恒等于时间窗数。 |
| **ROI 可编辑位置** | **仅在 `分析 → 对齐` 页标定**。分段页只读，不允许微调 ROI。 |
| **视频零点** | 人工标定 `offset_seconds`，默认 `0`；未标定时 `aligned=false`，如实在界面与 manifest 标记。 |

## 3. 核心领域模型

### 3.1 统一坐标系与模态映射

**基准轴 = 信号时间轴**，原点为信号首个采样点，单位秒。其他模态各自维护一条映射，把统一轴上的时刻换算到本模态的坐标。

```json
{
  "schema_version": 1,
  "unified_axis": { "unit": "second", "origin": "signal_first_sample", "duration": 182.0 },
  "event_bounds": { "start": 0.24, "end": 181.4 },
  "mappings": {
    "timeseries": { "type": "identity", "available": true, "calibrated": true, "reason": null },
    "video": {
      "type": "linear",
      "available": true,
      "calibrated": false,
      "offset_seconds": 0.0,
      "fps": 30.0,
      "duration": 180.9,
      "reason": "时间零点未标定，关键帧按假设对齐"
    },
    "seam_image": {
      "type": "arc_length",
      "available": true,
      "calibrated": true,
      "object_key": "raw/SP2026-06-000201/202.jpg",
      "roi": { "x": 120, "y": 300, "w": 1706, "h": 260 },
      "speed_source": "channel",
      "reason": null
    },
    "audio": { "type": "none", "available": false, "calibrated": false, "reason": "源未附加" }
  }
}
```

**统一判定规则**：

```text
aligned = available && calibrated
```

未标定的模态不再声称 `aligned=true`。视频轨沿用音频/红外轨同样的诚实标准。

#### 3.1.1 视频映射（`linear`）

```text
t_unified = t_video + offset_seconds
t_video   = t_unified - offset_seconds
```

`offset_seconds` 语义：**视频第 0 帧出现在统一轴上的时刻**。`offset=0.5` 表示视频比信号晚开 0.5 秒。取统一时刻 `t` 的视频帧即 `ffmpeg -ss (t - offset_seconds)`。

`offset_seconds` 为负表示视频早于信号开始。

#### 3.1.2 焊缝图片映射（`arc_length`）

焊缝图片的空间轴是沿焊缝的累计长度。设焊接速度 `v(τ)`，则从有效焊接区间起点 `E_start` 到统一时刻 `t` 的累计弧长为：

```text
L(t) = ∫[E_start → t] v(τ) dτ
L_total = L(E_end)
r(t) = L(t) / L_total              # 位置比例，0..1
px(t) = roi.x + r(t) × roi.w       # 沿 ROI 长边的像素位置
```

**时间窗 `[t_s, t_e)` → 像素区间 `[px(t_s), px(t_e))` → 该区间内的 ROI 条带即本样本的焊缝图片切片。**

该式不含任何物理长度，因此**不需要像素标定**。前提是焊缝照片覆盖整个有效焊接区间（由人工框选确认）。

`speed_source` 按数据可得性三级降级，如实记录用了哪一级：

| `speed_source` | 数据条件 | 算法 | 界面/manifest 标记 |
|---|---|---|---|
| `channel` | CSV 含 `weld_speed` 通道（别名 `焊接速度`/`WeldingSpeed`/`welding_speed`，见 `signal_ingest.py:96`） | 积分弧长 `∫v dτ` | 无额外提示 |
| `scalar` | 无通道，但有登记单值 `data_records.welding_speed`（系统回填的**稳态中位数**，`signal_ingest.py:799-802`） | 恒速退化 → `r(t) = (t - E_start)/(E_end - E_start)` | warning「按焊接速度稳态中位数映射，未使用逐点速度」 |
| `none` | 两者皆无（如 `SP2026-06-000201.csv`） | 纯时间比例映射 | warning「未使用真实焊接速度，按时间比例映射」 |

后两级在数学上均为恒速假设。**`none` 不阻断分段**——焊缝图片依然可切、可关联，只是如实标注未使用真实速度。这比"没有速度就不做"更有用。

### 3.2 时间窗口

对有效区间 `[E_start, E_end]`，切片时长 `W`、步长 `S`：

```text
window_i.start = E_start + i × S
window_i.end   = window_i.start + W
```

仅当 `window_i.end <= E_end` 时产生完整窗口。窗口序号从 1 开始，窗口用半开区间 `[start, end)` 表示，避免相邻切片对边界资源重复归属。采样点、视频帧与图片像素均从秒经**映射**换算得到：

```text
signal_start_index = ceil(start × sample_rate)
signal_end_index   = ceil(end × sample_rate)
video_start_frame  = ceil((start - offset_seconds) × fps)
video_end_frame    = ceil((end - offset_seconds) × fps)
image_start_px     = roi.x + r(start) × roi.w
image_end_px       = roi.x + r(end) × roi.w
```

真实实现需采用同一套浮点容差和取整函数，且在 manifest 中保存原始秒值；采样点/帧号/像素是派生信息，不得反向成为切分规则。

窗口切片在任一模态越界时（如视频起点晚于窗口起点），该模态在本窗内标记为缺失，不伪造内容。

### 3.3 多模态样本包

一个 `Sample` 代表一个时间窗，不再代表“图像样本”或“信号样本”。建议新增/规范化下列 `meta`：

```json
{
  "schema_version": 3,
  "sample_index": 5,
  "time_range": { "start": 8.0, "end": 10.0, "duration": 2.0 },
  "source": { "weld_id": "WLD-20260903-0002", "version_id": 102, "mapping_version": 1 },
  "signal": {
    "available": true,
    "sample_rate": 5000,
    "start_index": 40000,
    "end_index": 50000,
    "channels": ["cur", "vol", "gas", "wir"]
  },
  "video": {
    "available": true,
    "object_key": "raw/.../weld.mp4",
    "fps": 25.0,
    "offset_seconds": 0.5,
    "start_frame": 200,
    "end_frame": 250,
    "keyframes": [{ "at": 8.0 }, { "at": 9.0 }, { "at": 9.96 }]
  },
  "seam_image": {
    "available": true,
    "object_key": "raw/.../202.jpg",
    "roi": { "x": 120, "y": 300, "w": 1706, "h": 260 },
    "spatial_range": { "start_px": 120, "end_px": 341 },
    "crop_key": "processed/.../split/{task_id}/samples/000005.jpg"
  },
  "audio": { "available": false, "reason": "source_not_attached" }
}
```

`available=false` 与空数组语义不同：前者是源模态不存在或不可解析，后者表示该模态存在、但这个时间窗内没有资源。这样数据集构建和模型训练可以正确判断缺失原因。

`seam_image` 用 `spatial_range` 而非 `captured_at`——它没有采集时刻，只有沿焊缝的位置。`time_range` 仍是它的主键，`spatial_range` 是映射的派生结果。

### 3.4 版本与兼容

- 新任务写入 `rules_version=3`、`schema_version=3`；版本 1/2 的任务仍按原逻辑读取，不在同一页面伪装为新格式。
- 新页面默认只显示新版“多模态时间统一”任务；历史任务在“历史切分任务”只读列表中保留下载和追溯入口。
- `task_format` 从切分规则和任务实体中废弃。短期兼容字段可保留为 `null`，但不得再影响产物生成。
- 标定（`calibration`）挂在**源版本**上；对齐任务读源版本标定，算出映射写入 `alignment_tasks.mapping`，并产出新的“时间对齐”版本。
- 标定或映射变更后，此前按旧映射生成的历史分段任务不自动重算，提供“按新映射重新分段”入口生成独立新任务。

## 4. 交互与界面设计

### 4.1 两段式工作流

```text
分析 → 对齐（标定层）              分析 → 样本分段（切分层）
  建立统一坐标系                      消费坐标系，切窗
  视频零点 offset 标定                只读标定与映射
  焊缝图片 ROI 框选                   调整时长/步长/事件边界
  焊接速度来源确认                    多模态预览 + 确认生成
  产出 mapping + 新版本               产出样本包
```

**标定只在对齐页发生一次，分段页只读。** 这个划分是“所见即所得”的前提：分段页上看到的边界必须完全由服务端预览决定，不能再引入一个本地可改的标定参数。

### 4.2 对齐页：标定工作台

```text
左：模态对照工作区
  [信号波形 + 事件边界]        ← 统一轴的基准
  [视频播放器 / 帧缩略带]       ← 可拖 offset
  [焊缝照片 + ROI 框选]         ← 可拖框、可缩放手柄

右：标定面板
  视频零点 offset：____ 秒（滑块 + 数字，实时预览对应帧）
  焊缝图片 ROI：x/y/w/h（图上拖拽回填）
  焊接速度来源：通道 weld_speed / 登记单值 / 无（只读，自动判定并说明）
  [保存标定]  [运行对齐任务]

下：一致性提示
  视频时长 180.9s 比信号 182.0s 短 1.1s，零点可能未对齐
  未标定的模态不会声称已对齐
```

- 拖动 offset 时，同屏信号游标与视频画面同步移动，用户对准起弧时刻即可。
- ROI 框选使用轴对齐矩形；焊缝在框内大致水平即可。倾斜焊缝的旋转矩形留作后续升级。
- 保存标定写 `data_versions.calibration`；运行对齐任务时服务端据此计算映射。
- 标定的实时反馈在前端本地完成（规则是纯函数、只读、不产出）；**保存与映射产出必须经服务端**。

### 4.3 分段页：切分工作台

```text
步骤条：1 数据检查  →  2 规则与预览  →  3 确认生成

左：多模态统一时间轴（主工作区）             右：固定时间切分规则
  [总览标尺 + 当前窗口/事件范围]                   有效事件起点、终点（滑块+数字）
  [电流/电压/音频等时序轨]                         切片时长：2.0 秒
  [视频缩略图轨]                                   切片步长：2.0 秒
  [焊缝图片投影带]                                 事件缓冲：开关 + 秒数
  [贯穿所有轨道的切片边界和选中高亮]                预计切片数 / 重叠 / 尾片策略
                                                   [标定状态：只读摘要 + 跳转链接]

下：选中切片详情
  时间窗、时序局部波形、视频首/中/末帧、焊缝图片切片、缺失模态说明
```

**分段页不可编辑标定。** 右侧面板的“标定状态”是只读摘要，显示 mapping 的可用性与标定状态；若用户需要调整 ROI 或 offset，提供“前往对齐页标定”链接，并在标定变更后要求重新预览。这不是限制，而是保证：分段页上任何一个边界都必须能在服务端复现。

### 4.4 切片边界和轨道规则

- 所有轨道横坐标按真实秒数线性映射，禁止各轨单独缩放。
- 边界线从时序轨顶部贯穿视频轨、焊缝图片带；边界使用高对比强调色，选中窗口使用低透明度背景。
- 视频轨显示连续抽样缩略图；点击任意缩略图定位对应时间。视频未加载时显示明确状态而非空白。
- 焊缝图片带按 §3.1.2 的映射投影：整张照片横向铺开为背景，边界线按 `px(t)` 垂直落在照片上，每段的裁剪条带即该样本的图片切片。照片未框选 ROI 时，该带显示“未标定”状态而非空白。
- 时序轨默认展示电流、电压及可用音频包络；通道过多时可开关，但切片边界始终固定显示。
- 点击边界相邻区域、下方切片卡片或概览中的窗口均选中同一切片；选中后视频 seek 到窗口起点（经 offset 换算），详情区展示该窗口内容。

### 4.5 实时预览状态机

```text
规则初始值 / 用户编辑
  → 本地同步校验（时长、步长、边界）
  → 300 ms 防抖
  → POST split-preview
  → 成功：替换窗口、轨道边界、预计数和详情
  → 失败：保留上一份成功预览，显示可操作错误

用户点击“确认生成样本”
  → 必须使用当前成功预览返回的 preview_token
  → POST split-tasks
  → 轮询 Job
  → 成功：显示任务 ID、样本数与可进入标注/数据集的入口
```

实时预览期间不自动创建 Job。输入不合法、请求在途、当前规则与成功预览不一致时，“确认生成样本”均不可用。

### 4.6 校验与错误提示

| 情形 | 行为 |
|---|---|
| 时长或步长 ≤ 0 | 输入框字段错误，不发预览请求。 |
| 有效区间短于时长 | 预览显示 0 个完整样本及修正建议，不允许创建。 |
| 步长小于时长 | 允许；显示“重叠 X 秒（Y%）”。 |
| 视频不存在/帧率不可测 | 不阻止分段；视频轨和样本详情标记不可用。 |
| 视频 offset 未标定 | 不阻止分段；视频轨标“未标定”角标，样本 manifest 记 `calibrated=false`，预览给 warning。 |
| 焊缝图片未框选 ROI | 不阻止分段；图片带显示“未标定”，样本 manifest 记 `available=false` + reason。 |
| 焊缝图片无焊接速度数据 | 不阻止分段；按 `speed_source=none` 纯比例映射，给出 warning。 |
| 时序信号不存在或事件无效 | 阻止生产分段；说明需先完成真实信号导入或修正事件边界。 |
| 分段页尝试修改标定 | 不允许；提示前往对齐页。 |
| 规则编辑中接口失败 | 保留上一版可用预览及其时间戳，明确当前编辑未应用。 |

## 5. API 契约

### 5.1 标定（对齐层）

`GET /api/v1/welds/{weld_id}/versions/{version_id}/calibration`

返回当前标定与标定工作台所需数据：

- `calibration`：`video.offset_seconds`、`seam_image.roi`，以及各项的 `calibrated` 标记；
- `modalities`：各模态可用性、原因、元信息（视频 `duration`/`fps`/`width`/`height`，图片尺寸）；
- `speed_source`：自动判定的焊接速度来源（`channel` / `scalar` / `none`）及依据说明；
- `timeline`：统一轴总时长、事件边界、时序降采样数据；
- `media`：视频与图片的短期签名 URL；
- `warnings[]`：如“视频时长比信号短 1.1 s，零点可能未对齐”。

`PUT /api/v1/welds/{weld_id}/versions/{version_id}/calibration`

请求体：

```json
{
  "video": { "offset_seconds": 0.5 },
  "seam_image": { "roi": { "x": 120, "y": 300, "w": 1706, "h": 260 } }
}
```

写入 `data_versions.calibration`。不做重计算，不建 Job。返回规范化后的标定与 `calibrated` 状态。

### 5.2 对齐任务与映射产出

`POST /api/v1/welds/{weld_id}/versions/{version_id}/alignment-tasks`

请求体保持 `{ "modalities": [...] }`（现有契约），服务端额外读取已保存的 `calibration` 参与映射计算。

`GET /api/v1/alignment-tasks/{task_id}` 的响应新增 `mapping` 字段（§3.1 的结构），前端据此展示每个模态的 `aligned` 真实状态。产物新增 `processed/{weld_id}/align/mapping.json`。

### 5.3 分段预览

`POST /api/v1/welds/{weld_id}/versions/{version_id}/split-preview`

请求体：

```json
{
  "window_seconds": 2.0,
  "stride_seconds": 2.0,
  "event_start": 0.24,
  "event_end": 18.2,
  "keep_event_buffer": 0.0,
  "tail_policy": "drop"
}
```

**请求体不含标定参数**——映射恒从源版本的 `calibration` 与对齐版本的 `mapping` 读取。响应包含 `preview_token`（规则、源版本、有效边界、映射版本与窗口算法版本的不可变摘要），以及：

- `effective_range`、`window_seconds`、`stride_seconds`、`overlap_seconds`、`tail_policy`、`sample_count`；
- `windows[]`：每个窗口的 `index/start/end` 和各模态映射摘要（含 `video.start_frame`/`seam_image.spatial_range`）；
- `timeline`：统一总时长、事件、时序降采样数据、视频缩略图时间点、焊缝图片投影位置；
- `modalities`：每个模态的可用性、标定状态、原因、元信息；
- `warnings[]`：不阻断但需要用户知晓的对齐/缺失问题。

预览只读，返回资源 URL 时使用短期签名 URL 或按需请求文件 URL，禁止把原始媒体字节塞进 JSON。

### 5.4 创建任务

`POST /api/v1/welds/{weld_id}/versions/{version_id}/split-tasks`

请求体只接受：

```json
{ "preview_token": "spv_..." }
```

服务端验证 token 的焊缝、版本、过期时间、规则哈希**及映射版本哈希**；随后用 token 对应规则与映射重新构建窗口。禁止客户端再次提交一套独立规则或标定，以避免“所见即所得”失效。若源版本、事件数据或标定已改变，返回 `409` 并要求重新预览。

### 5.5 查询任务和样本

- `GET /split-tasks/{task_id}`：返回任务状态、规则摘要、映射摘要、产物 manifest、样本数和新版 schema 标识。
- `GET /split-tasks/{task_id}/samples?page=&page_size=`：服务端分页返回每个时间窗及多模态摘要。
- `GET /split-tasks/{task_id}/samples/{sample_id}`：返回单窗口详情、时序局部数据和按需生成的媒体访问地址。

分页列表不返回完整高频时序数组或大尺寸图片，以避免大量切片时首屏失控。

## 6. 后端实现设计

### 6.1 服务划分

**对齐层（`app.services.alignment`，职责扩展）**：

1. `resolve_calibration()`：读取并规范源版本的 `calibration`，校验 ROI 在图片范围内、offset 在合理区间。
2. `build_coordinate_mapping()`：构建 §3.1 的映射对象。视频按 `linear` 换算，图片按 `arc_length` 换算，`speed_source` 自动判定三级降级。
3. `arc_length_profile()`：按 `weld_speed` 通道积分出 `L(t)`；无通道时退化为恒速比例。供上式与预览共用。
4. `_build_tracks()`（改造）：`aligned` 由 `available && calibrated` 推导，不再硬编码 `True`；焊缝图片从 `infrared` 桶中析出为独立 `seam_image` 轨道。

**分层（`app.services.splitting`，拆为清晰的无副作用组件）**：

5. `resolve_effective_range()`：事件边界 + 用户修正 + 缓冲，输出可审计有效区间。
6. `build_time_windows()`：唯一的秒级窗口算法，供预览与 Job 调用。
7. `map_window_to_modalities()`：**经映射**为一个窗口生成样本包 manifest（不再自行乘 fps）。
8. `build_preview()`：对窗口、缩略图、时序数据和图片投影位置做受控抽样，只读。
9. `materialize_sample_artifacts()`：只在后续明确请求导出时，生成 CSV、关键帧、图片裁剪或短视频；分段 Job 默认只写 manifest 与图片裁剪。

`split.py` 只负责编排 Job、批量创建 `Sample` 行、上传 manifest、更新进度和失败回滚，不再直接决定“目标检测或时序分类”的单一产物，也不再自行做任何时间换算。

### 6.2 数据库迁移

建议新增迁移而不是覆盖历史记录：

- `data_versions.calibration`：JSON，存 §5.1 的标定结构；`null` 表示未标定。
- `alignment_tasks.mapping`：JSON，存 §3.1 的映射；与既有 `tracks`（轨道可用性展示）分离——两者消费方不同，`tracks` 供界面展示，`mapping` 供算法换算。
- `split_tasks.rules` 写入新版 JSON：`window_seconds`、`stride_seconds`、`effective_range`、`tail_policy`、`mapping_version`、`rules_version=3`。
- `split_tasks.task_format` 允许空值，后续迁移删除该列前先完成历史兼容窗口。
- `samples.meta` 写入 §3.3 的 `schema_version=3` 多模态映射；增加 `start_time`、`end_time` 两个数据库列及 `(split_task_id, start_time)` 索引，支持按时间筛选，避免对 JSON 全表扫描。
- 每个任务写一个 `manifest.json`，列出规则、源版本、映射版本、模态索引版本、样本清单和校验摘要。

### 6.3 存储策略

```text
processed/{weld_id}/align/mapping.json                          # 坐标映射（新增）
processed/{weld_id}/align/tracks.json                           # 轨道可用性（既有）
processed/{weld_id}/split/{task_id}/manifest.json
processed/{weld_id}/split/{task_id}/samples/{sample_id}.json    # 可选：单样本可独立读取
processed/{weld_id}/split/{task_id}/samples/{index:06d}.jpg     # 焊缝图片切片
processed/{weld_id}/split/{task_id}/derived/...                 # 仅按需导出的 CSV/关键帧/MP4
```

原始视频、图片和时序 Parquet/CSV 保持单份，样本 manifest 引用源对象键和时间范围。这样一个 30 分钟视频切成数百段不会立即复制为数百个 MP4。

### 6.4 性能边界

- 预览响应采用分层数据：时序 max 1,000–2,000 点/轨；视频缩略图最多 80 张；焊缝图片投影带为单张照片 + 边界线，无额外分块请求。
- 实时编辑防抖 300 ms，撤销前一个未完成的浏览器请求；服务端可按 `version + rules hash + mapping hash` 短期缓存预览结果（建议 TTL 60 秒）。
- 弧长积分 `L(t)` 按需缓存于对齐任务产出（`mapping.json` 可内联降采样折线），避免每次预览重算全量积分。
- Job 建样本时批量提交数据库行和 manifest，不为每个窗口做独立视频解码。
- 单个样本详情按需请求；关键帧与图片裁剪首次需要时生成并缓存到 `derived/`。

### 7.1 组件边界

对齐页在 `src/features/alignment/` 下扩展：

```text
AlignmentWorkspace.tsx        # 既有：模态对照、任务发起
CalibrationPanel.tsx          # 新增：offset 滑块 + ROI 回填 + 速度来源只读

```

```text
  SplitRulesPanel.tsx          # 秒级规则与事件边界 + 只读标定摘要
  MultimodalTimeline.tsx       # 共用比例尺、边界和选中窗口
```

前端不得自行计算正式窗口数量；可在输入时显示本地预估，但屏幕上的边界和“确认生成”必须以服务端成功预览为准。标定页的实时反馈可本地计算（纯函数、只读、不产出）。

### 7.2 状态约束

- `draftRules`：用户正在编辑的值。
- `appliedPreview`：最后一次成功响应，带 `preview_token`。
- `selectedWindowIndex`：从 `appliedPreview.windows` 中选择，不独立保存时间值。
- `isPreviewStale = hash(draftRules) !== appliedPreview.rules_hash`：为真时禁止创建任务。
- 分段页**不持有可编辑的标定状态**；标定只能来自服务端响应，且仅用于展示。
- 视频播放游标可以改变选中窗口，但播放行为不能修改规则、样本边界或标定。

## 8. 下游兼容与迁移策略

1. 先在对齐页落地标定与映射产出（`calibration` + `mapping.json`），用少量真实版本验收视频 offset 与焊缝图片投影。此阶段先修正现有 `aligned` 的虚假声明与 `welds.py:1067` 的假核验。
2. 再发布只读的新预览接口和新分段页面，验收时间对齐。
3. 启用新版创建任务；新任务均为 `rules_version=3`，旧任务继续在旧详情中可见。
4. 调整标注入口：从一个多模态样本包中选择“焊缝图片切片/视频关键帧/时序窗口”作为标注载体，而不是依赖 `task_format`。
5. 调整数据集构建：按模型任务声明所需模态（如 `signal+video`、`signal+seam_image`），筛选同时具备所需资源的样本；不符合的样本给出可解释的排除原因。
6. 目标检测所需的固定像素尺寸 tile（如 512×512），在数据集构建阶段由 `materialize_sample_artifacts()` 从样本的图片裁剪派生，不为它单开一条切分链路。
7. 历史 `rules_version <= 2` 不自动重算；提供“按新规则/新映射重新分段”入口，生成独立新任务和新版本。

## 9. 验收标准

### 9.1 规则一致性

- 默认打开页面显示 `2.0 秒`时长与 `2.0 秒`步长。
- 修改为 `1.5 秒 / 0.5 秒`后，预览、样本数、红线边界、最终任务 manifest 的窗口完全一致。
- 相邻非重叠窗口没有时间间隙或重叠；重叠规则按步长准确产生重叠。
- 所有窗口边界均在有效事件范围内；默认尾片不生成。
- 预览与 Job 对同一规则返回相同窗口数、起止时间。

### 9.2 坐标映射与多模态对齐

- 视频 offset 标定后，统一时刻 `t` 抽取的关键帧确为视频 `t - offset` 处的帧；offset 从 0 改为 0.5，抽出的帧相应后移。
- 未标定 offset 时，视频轨显示 `aligned=false` 与未标定原因，样本 manifest 记 `calibrated=false`；**不得显示为已对齐**。
- 焊缝图片 ROI 框选后，时间窗 `[t_s, t_e)` 投影出的像素区间与照片上该段焊缝实际位置一致（人工目视核对）。
- 焊缝图片切分段数恒等于时间窗数；不存在“图片切出 N 段而时间窗有 M 个”的不一致。
- `speed_source` 三级降级均产出可用的投影；`scalar`/`none` 两级的 warning 在界面与 manifest 中如实出现。
- 无任何焊接速度数据时（`SP2026-06-000201.csv` 场景），焊缝图片仍能切分并关联，标记为纯比例映射。
- 点击任一窗口，时序局部曲线、视频关键帧和焊缝图片切片均对应同一时间范围。
- 缺失模态不伪造内容，界面与 manifest 均给出原因。

### 9.3 交互与安全

- 用户连续输入时不产生多个 Job；仅成功预览允许确认创建。
- 创建任务必须使用未过期且与当前源版本、映射版本一致的 `preview_token`。
- **分段页无法修改标定**：界面上不存在可编辑的 ROI 或 offset 控件；标定变更后旧 `preview_token` 失效并返回 `409`。
- 大样本预览保持受控：不传输完整视频和全量高频信号。
- `services/welds.py` 的「多模态时间戳对齐」核验项不再无条件通过；无标定时给出 warning 或 failed。

## 10. 实施拆分与风险

| 阶段 | 交付 | 主要风险与控制 |
|---|---|---|
| A | 标定模型 + 坐标映射 + 对齐任务改造（`calibration` 表列、`mapping.json`、`arc_length_profile`、`aligned` 诚实化） | 建立固定的映射单测：offset 符号、弧长积分、三级降级、ROI 越界。先修 `welds.py:1067` 假核验止血。 |
| B | 对齐页标定工作台（offset 滑块、ROI 框选、速度来源只读、一致性提示） | 标定实时反馈本地算、保存走服务端；ROI 越界与极端长宽比需防御。 |
| C | 新窗口算法、预览契约、分段页多轨预览 | 以单测固定边界、取整、尾片、重叠案例；只采用服务端成功预览绘制正式边界；防抖+取消旧请求。 |
| D | 新多模态 manifest、数据库迁移、Job 编排、图片裁剪落盘 | 新旧 `rules_version` 隔离，绝不修改历史任务；图片裁剪失败不阻断样本创建。 |
| E | 单样本详情、按需派生产物、标注/数据集消费适配 | 先引用原始媒体，避免批量生成文件与存储膨胀。 |
| F | E2E、性能与真实数据验收 | 覆盖有/无视频、有/无图片、未标定 offset、未框选 ROI、无焊接速度、重叠、短事件等场景。 |

**阶段依赖**：A 是所有后续阶段的前提——坐标系不定，B/C/D 全都缺基准。建议 A 单独验收后再并行推进 B 与 C。

## 11. 已确认前提

原方案列为“实施前必须确认”的三条，经排查后重新定性：

1. **~~图片必须具备可解析的采集时间戳~~ → 已消解。** 焊缝图片不是时间模态，其轴是沿焊缝的长度。原前提源于把图片误当作“按时间连续采集的图片”（那实际是视频）。焊缝图片改按空间模态处理，不需要 EXIF、文件名解析或上传清单。
2. **~~视频与时序须已对齐到同一时间零点~~ → 从“前提”改为“交付物”。** 该对齐既未实现也不应作为外部前提，而是本方案阶段 A 要产出的映射。当前实测偏差 1.1 s 且静默发生，必须由标定显式化。
3. **默认 `2 秒` 仅是初始值，不是固定限制** —— 保留为提醒。代码现状已满足（`splitting.py::build_windows` 完全参数化，无 2 秒硬编码）；待办的是移除前端“按帧切分”入口，属产品决策。

**新增数据前提**：焊缝照片必须覆盖整个有效焊接区间，时间比例才等于空间比例（`none`/`scalar` 两级）或弧长积分才成立（`channel` 级）。该前提由人工框选 ROI 的动作确认，不另设校验。

### 12.7 独立线索：TypeSafe 用于「焊接方法 → 过渡类型」

排查中发现一处**与本方案无关但已在实际出错**的地方，形状属「自然语言 → 类型化判断」，确定性代码做不到：

```python
# backend/app/services/dashboard.py:28-38
TRANSITION_BY_WELD_METHOD = {
    "MAG焊": "短路过渡", "MIG焊": "射流过渡", "TIG焊": "混合过渡",
    "埋弧焊": "脉冲过渡", "CMT": "CMT",
}
UNKNOWN_TRANSITION = "未分类"   # dashboard.py:126 用 .get(method, UNKNOWN_TRANSITION)
```

S2 放开登记页「焊接方法」自由输入后，这个**五键精确匹配**接不住现场写法（`MAG焊（富氩）`、`气保焊`、`mag`、`CO₂焊`…），全部落进「未分类」，总览的过渡类型分布退化。改造前兜底是「脉冲过渡」（静默算错），现在改成「未分类」只是停止说谎，分布仍然是废的。

**动手前必须先验的前提**（未验之前属过度设计）：

```sql
SELECT weld_method, COUNT(*) FROM data_records GROUP BY weld_method ORDER BY 2 DESC;
```

实际只有那 5 种 + 零星几个 → `未分类` 是可接受兜底，不做；有几十种现场写法散落在 `未分类` → 真需求，值得用 TypeSafe 的 `Choice` 做「给定自由文本 + 已知类别集，选出最匹配者」。

**可行性**：仓库未配 TypeSafe 凭据（`.env` / `backend/app/core/config.py` 均无 `TYPESAFE_*`），要做需先申请 key，并按 `docs/开发规范.md` 落 `.env`。
