# ForgeLab 菜单与页面功能测试计划

## 1. 文档目的

使用 Playwright CLI 对当前已完成全栈接线的焊接数据智能分析与 AI 建模平台进行业务功能验收。测试以产品目标、信息架构和用户业务闭环为依据，验证真实 API、数据库、对象存储和异步 Job 在浏览器中的完整表现，而不是根据当前代码“有什么”反推“应该测什么”。重点确认：

1. 一级菜单和子菜单能够正常显示、展开、收起和切换。
2. 每个子菜单展示内容符合当前功能设计。
3. 主要按钮可点击，点击后有明确的页面、状态、弹窗、任务或导出效果。
4. 未满足前置条件时，页面能够给出明确提示，而不是白屏或无响应。

本计划是浏览器端业务功能验收计划，不替代后端接口契约、算法专业精度、数据库约束、对象存储一致性、权限安全和压力测试；这些内容须与 API/后端测试联合判定。

### 1.1 当前项目阶段与验收原则

当前项目已从前端原型阶段进入真实系统功能验收阶段：

- 前后端 API 已完成主要业务链路接线，登录、数据上传、数据核验、版本、数据集、异步 Job、报告导出和对象存储均纳入真实流程。
- 信号导入、时域/频域/时频分析、异常分析、特征提取及分析报告已经支持真实数据链路；测试必须验证真实数据来源和真实产物，不能只验证页面有图表。
- 多模态对齐已经接入真实视频探测、真实信号事件和真实产物；切分、标注、训练、测试、推理中的部分计算内核仍属于演示/模拟算法，但任务创建、状态持久化、结果回填和产物关联仍必须按真实系统验收。
- 演示数据只用于初始化环境或明确的失败兜底，不得在真实 API 成功前闪现为真实结果，也不得把演示指标当作算法质量结论。
- API 失败时，页面应显示明确的错误或空状态，不得静默展示过期、串数据或无法标识来源的内容。

通过标准优先回答三个问题：用户是否能完成正确的业务决策、系统是否保持数据与版本上下文一致、失败后用户是否知道发生了什么以及下一步怎么做。

### 1.2 核心业务验收主线

本计划按以下业务顺序执行，菜单结构只负责提供入口，不改变业务依赖关系：

| 阶段 | 业务目标 | 主要验收内容 |
|---|---|---|
| 1. 数据集/焊缝数据 | 建立并确认业务数据对象 | 数据集列表、数据集概览、数据上传、焊缝成员、数据详情 |
| 2. 数据版本 | 确认当前处理输入和历史版本链 | 原始版本、处理版本、最新版本、版本详情和版本上下文 |
| 3. 数据核验 | 判断数据是否具备继续处理的质量基础 | 15 项规则、质量状态、报告、失败和重试 |
| 4. 分析与标注 | 基于已选焊缝和版本生成分析结果与标注结果 | 多模态对齐、信号分析、切分、图像/时序/视频标注、特征提取 |
| 5. 固定数据集版本 | 把可用样本固化为可复现的训练/验证/测试快照 | 数据集构建、成员清单、划分、质量、血缘和模型适配检查 |
| 6. 模型训练 | 使用固定快照创建训练任务和模型版本 | 模型资产、训练配置、Job、日志、指标和模型版本 |
| 7. 测试评估 | 使用独立固定测试数据评价模型 | 测试任务、指标、混淆矩阵、推理时延和报告 |
| 8. 推理验证 | 使用模型对新图片/视频执行验证 | 文件输入、推理 Job、类别、置信度、耗时和失败处理 |

每进入下一阶段，都必须验证上一阶段产物确实存在且上下文一致；不能只通过直接打开下游菜单来替代完整链路验收。

## 2. 当前测试范围

当前侧边栏包含 4 个业务一级菜单、15 个子菜单：

| 一级菜单 | 子菜单数量 | 子菜单 |
|---|---:|---|
| 数据总览 | 0 | 数据总览 |
| 数据中心 | 4 | 数据集、数据上传、数据核验、数据版本 |
| 分析与标注 | 6 | 选择数据、多模态对齐、信号分析、样本分段、数据标注、特征提取 |
| 模型中心 | 5 | 训练数据准备、模型资产、新建训练、测试评估、推理验证 |

侧边栏另有“系统设置”按钮。若当前版本仍展示该入口但没有可用页面，应记录为产品能力缺口/待开发项，不得作为功能通过；若产品决定本期不支持，应在菜单中隐藏或明确标识规划状态。

除侧边栏子菜单外，数据集页面还包含页面内部视图：

- 数据集列表
- 数据集概览
- 当前版本数据
- 全部数据
- 单条焊缝详情
- 版本详情抽屉

## 3. 测试前置条件

### 3.1 服务环境

建议使用隔离的测试环境，启动前端和后端服务：

```powershell
npm install
npm run dev
```

根据项目实际配置启动后端、数据库和对象存储。默认前端地址假设为：

```text
http://localhost:5173
```

执行前确认本地 CLI 可用：

```powershell
npx playwright --version
```

如果浏览器尚未安装：

```powershell
npx playwright install chromium
```

### 3.2 测试账号和数据

需要准备：

- 可登录的测试账号和密码。
- 至少一个数据集。
- 至少一条焊缝数据。
- 至少一个包含真实 CSV、图片、视频或 WAV 文件的数据记录。
- 至少一个已生成版本的数据集。
- 至少一个可训练数据集版本。
- 至少一个模型及模型版本。

如果没有真实数据，仍可执行菜单、空状态、禁用状态、表单校验和页面布局测试，但不能判定上传、异步任务、真实信号和模型结果是否正确。

### 3.3 建议准备的文件

```text
fixtures/
  valid-signal.csv
  valid-image.jpg
  valid-video.mp4
  valid-audio.wav
  empty.csv
  invalid-format.txt
  broken-image.jpg
```

## 4. Playwright CLI 基础操作约定

本计划使用 Playwright CLI 进行探索式验证。CLI 的具体子命令以当前安装版本输出为准：

```powershell
npx playwright --help
npx playwright codegen http://localhost:5173
```

建议每个测试场景都保留以下证据：

- 操作前后页面截图。
- 关键页面标题或状态文本。
- 失败时的控制台日志和网络请求信息。
- 下载文件或弹出窗口的结果。

通用验证原则：

- 页面切换后验证页面标题、核心说明文字和主要面板。
- 不只验证按钮“能点击”，还要验证点击后出现的状态变化、数据变化、弹窗、任务号、错误提示或下载结果。
- 当前应用主要使用 React 内部路由状态，菜单切换不一定改变 URL，因此优先通过可见文本、角色和页面结构验证，不把 URL 变化作为唯一判定依据。
- 对异步任务使用“状态文本变化”作为核心断言，例如“处理中”“已完成”“失败”。

## 5. 全局菜单测试

### NAV-001 登录闸门

操作：

1. 清除 token 或使用无痕浏览器打开首页。
2. 查看初始页面。
3. 输入正确账号密码登录。

预期：

- 未登录时显示登录页，不显示业务侧边栏。
- 错误账号或密码显示明确错误信息。
- 登录成功后出现 ForgeLab、工作空间、侧边栏和“数据总览”。

### NAV-002 一级菜单显示

预期显示以下业务菜单：

```text
数据总览
数据中心
分析与标注
模型中心
系统设置
```

其中“数据中心”“分析与标注”“模型中心”应显示展开/收起箭头。

### NAV-003 菜单展开和收起

操作：依次点击三个带子菜单的一级菜单，再次点击当前一级菜单。

预期：

- 点击后显示对应子菜单。
- 再次点击后收起子菜单。
- 当前工作空间保持 active 样式。
- 从一个工作空间切换到另一个工作空间后，目标工作空间自动展开。

### NAV-004 子菜单切换

操作：逐个点击 15 个子菜单。

预期：

- 子菜单按钮显示 active 样式。
- 页面标题、说明文字和主体面板与目标菜单一致。
- 页面不白屏，不出现 React 未捕获异常。
- 需要上下文的页面在未选择数据时显示“请先选择数据集和焊缝数据”或等价提示。

### NAV-005 系统设置当前状态

操作：点击“系统设置”。

预期：

- 按钮可以被定位和点击。
- 当前版本不应误跳转到不存在页面或出现无反馈状态。
- 如果入口属于本期范围，必须进入可用的设置页面并完成相应功能验收。
- 如果入口不属于本期范围，记录为“产品能力缺口/待开发”，不能记为通过项。

## 7. 数据中心测试

### DATASET-001 数据集列表显示

操作：进入“数据中心 → 数据集”。

预期显示：

- 数据集列表标题和说明。
- 新建数据集按钮。
- 数据集名称、任务类型、样本数、标注完成度、当前版本、状态。
- 可训练数据集数量。
- 加载中、空列表和请求失败时有明确状态。

### DATASET-002 新建数据集

操作：点击“新建数据集”，输入名称并确认。

预期：

- 打开新建数据集弹窗。
- 弹窗包含数据集名称输入框、取消和确认按钮。
- 取消后弹窗关闭且不创建数据。
- 确认后弹窗关闭，出现新数据集或成功提示，列表重新加载。
- 空名称不能提交，或显示明确校验信息。

### DATASET-003 数据集概览

操作：点击一个数据集列表行。

预期显示：

- 数据集名称、任务类型、来源、当前版本和状态。
- 数据集样本数、标注完成度、训练/验证/测试划分、数据质量。
- 数据集版本列表。
- 数据血缘。
- “查看全部数据”和“查看当前版本”按钮。
- 没有固定版本时显示没有版本的空状态，不能伪造旧版本；主操作应引导用户创建数据集版本。

### DATASET-004 数据集版本详情

操作：点击数据集版本或“查看详情”。

预期：

- 打开版本详情抽屉。
- 显示快照 ID、样本数、训练/验证/测试比例和数据质量。
- 点击关闭按钮或遮罩后抽屉关闭。

### DATASET-005 当前版本数据

操作：点击“查看当前版本”。

预期：

- 显示固定版本成员列表。
- 显示样本 ID、焊缝、登记编号、来源、焊机、模态、核验状态和数据划分。
- 支持关键词、核验状态和数据划分筛选。
- 支持版本切换。
- 支持分页，第一页时上一页按钮禁用，最后一页时下一页按钮禁用。
- 筛选无结果时显示空状态。

### DATASET-006 数据集成员数据

操作：点击“查看全部数据”。

预期：

- 显示当前数据集/数据集版本的固定成员，而不是调用全局焊缝列表后在前端过滤。
- 明确显示数据集名称、版本号、样本数和训练/验证/测试划分。
- 支持按焊缝 ID、名称或登记编号搜索，并确认筛选条件由服务端分页接口生效。
- 点击数据行进入焊缝详情；详情返回后仍回到原数据集和版本上下文。

### DATASET-007 焊缝详情和上下文跳转

操作：从数据列表点击一条焊缝。

预期显示：

- 登记编号。
- 当前数据版本。
- 核验状态。
- 所属数据集和所属版本。
- 数据划分。
- 可以从详情进入数据核验、数据版本或分析流程。
- 返回按钮返回正确的上一级视图。

### UPLOAD-001 数据上传页面

操作：进入“数据中心 → 数据上传”。

预期显示：

- 数据集选择。
- 数据来源。
- 采集时间。
- 焊缝/批次名称。
- CSV、图片、视频、WAV 音频文件选择控件。
- 上传或提交按钮。

### UPLOAD-002 表单必填校验

操作：不填写必填字段、不选择文件，尝试提交。

预期：

- 阻止提交，或显示明确的字段错误。
- 不产生无效登记记录。

### UPLOAD-003 正常上传

操作：填写完整表单并选择一个或多个合法文件提交。

预期：

- 显示上传中或处理中状态。
- 上传完成后显示成功结果、登记编号或数据记录。
- 数据集列表或数据详情能够看到新数据。
- 不重复产生相同文件或任务。

### UPLOAD-004 非法文件和失败处理

操作：分别上传空文件、损坏文件、不支持格式和超大文件。

预期：

- 显示明确错误。
- 上传失败时不会留下错误的业务记录。
- 页面仍可继续操作，不白屏。

### VALIDATION-001 未选择数据

操作：直接进入“数据核验”，不先选择焊缝。

预期：显示“请先选择数据集和焊缝数据”，并提供返回数据集或选择数据入口。

### VALIDATION-002 执行数据核验

操作：选择数据后进入核验页，点击开始核验。

预期：

- 显示当前焊缝和版本上下文。
- 显示处理中状态。
- 完成后显示质量分数、通过数、警告数和失败数。
- 失败时显示错误提示。
- 可以导出核验报告。

### VERSION-001 未选择数据

操作：直接进入“数据版本”。

预期：显示需要先选择数据的提示，不加载错误版本。

### VERSION-002 版本链和详情

操作：选择焊缝后进入数据版本，点击不同版本。

预期：

- 显示版本号和版本列表。
- 显示处理动作、操作人、备注、关联文件和核验结果。
- 可以打开和关闭版本详情。

## 12. 建议的执行顺序

菜单点击只作为入口级冒烟测试，主体必须按照产品业务闭环执行：

```text
导航冒烟：登录 → 一级菜单/子菜单 → 页面标题、权限和前置条件

数据治理闭环：数据集/焊缝数据 → 数据版本 → 数据核验

分析闭环：分析与标注 → 多模态对齐 → 信号分析 → 样本切分
  → 图像/时序/视频标注 → 特征提取

建模闭环：固定数据集版本 → 模型适配检查 → 模型训练
  → 测试评估 → 推理验证

横向回归：失败/重试 → 刷新和快速切换 → 重复点击 → 版本切换
  → 空数据 → 下载/导出 → 会话失效与审计取证
```

其中“数据集/焊缝数据 → 数据版本 → 数据核验 → 分析与标注 → 固定数据集版本 → 模型训练 → 测试评估 → 推理”是本计划的核心验收主线。不同角色可以从不同入口进入或跳过已完成步骤，但任何下游操作都必须继承并显示正确的数据、版本、数据集和任务上下文。

## 13. 通过标准

### 通过

- 15 个子菜单均能显示目标页面或明确的前置条件提示。
- 所有主要按钮均能被定位。
- 可操作按钮点击后有明确可观察效果。
- 禁用按钮的禁用原因符合页面前置条件。
- 页面没有白屏、未捕获异常或永久 loading。
- 失败场景能显示可理解的错误信息。
- 关键异步任务不会因为重复点击创建重复任务。

### 不通过

出现以下任一情况，需要记录缺陷：

- 菜单点击无响应或进入错误页面。
- 页面标题和菜单不匹配。
- 主要按钮可点击但没有任何反馈。
- API 失败时既无明确错误/空状态，又无可操作的下一步提示。
- 没有选择数据时误执行分析、标注、训练或测试。
- 任务失败后页面一直处于处理中。
- 重复点击产生重复业务记录。
- 导出按钮点击后既无下载也无错误提示。

## 14. 当前实现边界

当前系统已经具备真实业务编排和数据持久化能力，但部分算法计算内核仍为演示实现。因此本计划对不同能力采用不同验收标准：

- 对真实能力：验证真实输入、真实来源、真实产物、数据库/对象存储关联、报告内容和页面上下文。
- 对模拟算法能力：不单凭 Playwright 判定算法精度和模型质量，但必须验证任务能创建、轮询、成功/失败结束，结果与输入上下文关联，失败可解释，产物可追溯。
- 对所有页面：API 成功后只展示当前响应数据；API 失败显示明确错误或空状态，不得把静态回退内容冒充真实结果。
- 演示账号和 seed 数据仅用于验收环境初始化，不能降低真实链路的验收要求。

当前阶段的能力边界以现行契约和实现状态为准：信号导入、信号分析、特征提取、分析报告以及多模态对齐的真实输入/产物链路需要按真实能力验收；切分、标注、训练、测试、推理的部分计算结果仍需注明模拟算法边界，但其 Job、数据库记录、对象存储产物、版本关联和错误处理不能按“原型演示”降低要求。
