# 破坏性网页端测试指导

> 适用：对 AI 焊接平台做**破坏性/健壮性**网页端交互测试（鉴权绕过、注入、畸形输入、
> 边界、并发、负载、前端容错）。
> 目标系统：前端 `http://localhost:5173/ai_welding/`（Vite，`/api` 代理到后端 `:8000`），
> 后端 FastAPI + MySQL + MinIO。
> ⚠️ **前提：务必在隔离/已备份环境执行**，破坏性测试会污染数据（见 §1）。

---

## 0. 数据包在哪

测试数据包已生成在 `backend/tests/fixtures/destructive/`（26 个文件，含清单
`MANIFEST.md`；合法/畸形 CSV 分档、合法/损坏媒体、边界文件）。由
`backend/tests/fixtures/gen_destructive_data.py` 确定性生成，可随时重跑
（`cd backend && uv run python tests/fixtures/gen_destructive_data.py`）。
**不要用真实生产数据测试。**

## 2. 测试矩阵（按轮次，可勾选记录）

### 轮 1：只读探测（不产生脏数据）

| # | 操作（网页端） | 预期 |
|---|---|---|
| 1.1 | 未登录直接访问任意页面 → 被拦到登录页 | 登录闸门生效 |
| 1.2 | DevTools 篡改 `localStorage` token 为 `abc` → 刷新 | 跳回登录（或 401 后跳登录），不白屏 |
| 1.3 | 列表页搜索框输入 `' OR 1=1--`、`'; DROP TABLE users;--` | 正常返回（参数化查询），无异常数据/报错 |
| 1.4 | 搜索框/表单输入 `<script>alert(1)</script>`、`<img onerror=alert(1)>` | 页面按文本显示，**不弹窗**（React 转义） |
| 1.5 | 数据列表 URL 手改 `?page=999999`、`page_size=0`、`page_size=100000` | 不卡死；page_size 被封顶 100 |
| 1.6 | 分析页手改 URL 的 `mode`、`channel`、`filter_type` 为乱值 | 提示参数错误，页面不崩 |
| 1.7 | 地址栏直接访问 `/api/v1/files/..%2F..%2Fetc%2Fpasswd/url` | 404/400，不泄露文件 |
| 1.8 | 版本/详情页手改 URL id 为不存在/负数/超长 | 404/400，不白屏 |
| 1.9 | 用登录态把 `weld_name`/`product` 填超长文本（数千字） | 正常保存/显示或截断，不报错 |

> 本轮全过后，若 1.4 弹窗 → **XSS 漏洞**；若 1.5 卡死 → 分页未封顶（DoS）；若 1.3 返回异常 → SQL 注入。

### 轮 2：文件上传 / CSV 导入（半破坏，可在备份库做）

前置：数据管理 → 进入「数据登记」页（不要求先选，直接进）。

| # | 操作 | 用文件 | 预期 |
|---|---|---|---|
| 2.1 | 上传合法 CSV 并提交 | `csv/valid_5s_1khz.csv` | 登记成功；自动触发导入；分析页波形出现且标记**真实**信号 |
| 2.2 | 上传最小合法 CSV | `csv/valid_small_500.csv` | 通过校验 |
| 2.3 | 上传非数值 CSV | `csv/malformed_non_numeric.csv` | 校验失败，分析页回退「生成」信号，页面不崩 |
| 2.4 | 上传量程全超 CSV | `csv/malformed_out_of_range.csv` | 同上（fail） |
| 2.5 | 上传空/无表头 CSV | `csv/malformed_empty.csv`、`no_header` | 同上（fail） |
| 2.6 | 上传 BOM/UTF-16/坏行/超长行 CSV | `malformed_utf8_bom`、`utf16`、`inconsistent_columns`、`long_line` | 不崩溃；或 fail 或 warn，均有明确结论 |
| 2.7 | 上传大 CSV 看耗时 | `valid_large_100k.csv`（100k 行）→ `valid_huge_1m.csv`（1M 行） | 导入任务能完成；观察是否超时/内存暴涨 |
| 2.8 | 上传 0 字节文件 | `boundary/empty_0bytes.csv` | 拒绝或提示，不崩溃 |
| 2.9 | 上传 101MB 文件 | `boundary/oversize_101MB.bin` | 走大文件直传或拒绝；`size` 谎报时被拦截 |
| 2.10 | 上传合法视频 | `media/valid_weld.mp4` | 挂载后可播放（`getFileUrl`） |
| 2.11 | 上传截断 mp4 / 损坏 jpg / 空 wav | `media/broken_truncated.mp4`、`broken_corrupt.jpg`、`broken_empty.wav` | **前端优雅容错**（显示 broken 图标/错误提示），不白屏 |
| 2.12 | 上传伪类型 | `media/fake_type_evil.exe.mp4` | 接受或拒绝都行，**不得执行/渲染为脚本** |
| 2.13 | 上传解压炸弹 PNG | `media/bomb_10000x10000.png` | 前端预览/上传内存可控，不 OOM 卡死 |
| 2.14 | 上传超长文件名 / 路径穿越名 | `boundary/long_filename_*.csv`、`path_attack_..%2Fetc%2Fpasswd.csv` | 文件名被规范化，不出现目录穿越 |
| 2.15 | 同一 CSV 连续挂载两次 | 任选 | 只触发一次导入（幂等） |

> 重点观察：2.11 前端是否优雅降级；2.13 是否内存爆炸；2.15 是否重复建任务。

### 轮 3：并发 / 负载 / 暴力破解（真破坏，必须在备份/隔离环境）

| # | 操作 | 预期 |
|---|---|---|
| 3.1 | 并发重复提交同一登记表单（双击/脚本 50 连点） | weld_id 唯一约束拦重复，返回 409 而非 500 |
| 3.2 | 并发挂载同一 CSV 到同版本（脚本 20 并发） | 唯一约束兜底，不产生重复任务/500 |
| 3.3 | 一次性触发 100 个导入任务 | executor 轮询正常，无死锁/线程爆 |
| 3.4 | 50–200 并发刷总览/列表页 | 响应不雪崩，DB 连接池不耗尽 |
| 3.5 | **登录暴力尝试**（脚本用 `admin` + 弱口令字典反复登录） | ⚠️ 当前**无速率限制**——预期能一直试；这是已知风险 |
| 3.6 | 大 CSV 导入期间同时刷分析页 | 分析回退生成或等待，不互相拖死 |

> 3.5 与 3.4 是**当前最明确的风险点**（登录无节流、Job 执行器无并发上限）。

### 轮 4：前端健壮性

| # | 操作 | 预期 |
|---|---|---|
| 4.1 | 后端停掉，前端各页面刷新 | 保留 mock 数据（失败保留 mock），**不白屏** |
| 4.2 | 断网/后端恢复后自动重试 | 页面不永久卡 loading |
| 4.3 | 伪造 API 返回超大数组（DevTools 拦截 signals 返回 100 万点） | 前端抽稀 ≤512 点，不卡死 |
| 4.4 | 快速来回切换路由/刷新 | useEffect 竞态处理（`cancelled`），无报错闪烁 |
| 4.5 | 双击「保存标注」「开始训练」等按钮 | 不产生重复记录/任务 |

## 3. 日志取证与判定

- **每轮测完**看 `backend/logs/api.log`：
  - 预期 400/401/404/409 的请求应返回这些状态，**不得出现 500**（500 = 未兜底异常）
  - 观察 `duration_ms` 基线是否被破坏（异常慢请求）
- 数据库对照：`data_records`/`signal_ingests`/`jobs` 行数是否符合预期（无异常膨胀/重复）
- MinIO 对照：对象清单是否只多出预期上传
- **判定**：浏览器不白屏 + 预期状态码 + 无 500 + 无数据异常膨胀 = 通过

## 4. 恢复

- MySQL：`mysql -h <host> -P <port> -u root -p ai_welding < backup.sql`
- MinIO：删除测试期间写入的对象（按 `processed/`、`raw/` 前缀清点）
- 也可直接对测试库/桶 `drop` 重建后重跑 `alembic upgrade head` + 启动 seed

---

## 5. 已知风险点（建议测完修复）

1. **登录无速率限制**（§3.5）——argon2 慢哈希 + 无节流 = 暴力破解 + 并发 DoS
2. **Job 执行器无并发上限**（§3.3）——大量任务可能堆积
3. **seed 假文件**——演示数据 `object_keys` 指向 MinIO 不存在的对象，下载/播放 404
   （真实 CSV 导入后才有真文件；§2.10 用合法视频补上正路）
4. 单角色无细粒度权限——IDOR 面小但仍可试
