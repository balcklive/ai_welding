# 切片级特征提取（一期）设计与实施说明

> 2026-10。对应表 §3.28、接口 §3.10、迁移 `0021`。**已实施并跑通端到端**
> （`backend/tests/test_sample_features_e2e.py`，13 条：真实信号导入 → v3 分段（真视频抽帧）
> → 切片特征提取 → 构建数据集冻结 → 训练读到 36 维；含 §11 的单焊缝划分与"1 个样本仍被拒"边界）。

---

## 1. 为什么改

改造前是两套东西，而且两套都不对：

| 位置 | 粒度 | 算什么 | 落库 |
|---|---|---|---|
| `POST /features/extract-tasks`（页面「特征提取」） | **焊缝数据版本** | 42 维：**整条信号**逐通道统计 + **一整张**焊缝照片 + 声音 | `feature_extractions`，键只有 `version_id` |
| `torch_training._features_from_sample`（训练时） | **切片** | 8 维：按扩展名挑**一个**文件——帧图就转灰度 resize 32×32 取 256 像素算统计；否则把某个 CSV/JSON 的**所有数字**（连时间列）拉平算统计 | **不落库**，每次训练重算 |

后果：

1. **切片与那 42 维没有任何数据流**——页面算的那份训练用不上；
2. 训练真正吃的 8 维是"一张缩略图的灰度统计"或"一段 JSON 数字汤的统计"，做输入近乎噪声；
3. **不可复现**——不落库、每次现算，同一版本两次训练可能不同；
4. 改一次特征提取，已建数据集版本的训练输入会**静默改变**（如果真去读它的话）。

目标：**逐切片、落库、构建时冻结、训练读冻结值**。

---

## 2. 范围

**做**：切片级 36 维向量的计算 / 落库 / 读取 / 导出 / 工作台；构建数据集时冻进快照；训练改读冻结向量。

**不做**（一期）：框/点/掩膜级的局部特征；切片特征的历史版本
（重算原地 upsert，见 §5）；把版本级 42 维那条线删掉（报告导出与「特征提取」版本动作仍在用）。

## 3. 数据模型

见 `数据库设计.md` §3.28。要点：

- **`sample_features`**：`sample_id` **唯一键**（一个切片一行，PUT 即 upsert）；
  冗余 `split_task_id` / `version_id`（主读是"按任务列特征"、主写也按任务写，冗余后
  count/list/progress 是一次带索引查询，不必穿 `samples` join）。
- **为什么不给 `feature_extractions` 加 `sample_id`**：那张表的版本级端点
  （`GET /features/latest/{version_id}`、`/history/{version_id}`）按 `version_id` 取最新一行，
  切片行也带 `version_id` 就会被当成焊缝级向量返回。**分表让两边口径各自封闭。**
- **唯一键只取 `sample_id`（不是 `(sample_id, normalization)`）**：切片向量是**可再生派生产物**
  而非审计事件；复现性由冻结快照保证，而 `dataset_items` 一个 (version, sample) 只有一个槽位——
  留 N 个归一化变体与它自相矛盾。重算是原地 upsert，旧参数的数在**导出产物键**上留痕。
  升级路径（真要活历史）：把唯一键改成 `(sample_id, normalization)` 并给列表加筛选，成本很低。
- **`dataset_items.features`**：构建时写入的**同一份向量**。训练读快照而不现查 `sample_features`。

## 4. 特征定义：36 维

| 组 | 维度 | 来源 |
|---|---|---|
| 时序·电流 | 8 | 按该切片的**采样点区间**切**父版本信号**的 `cur` 通道 → `ts_features` |
| 时序·电压 | 8 | 同上 `vol` |
| 时序·气体 | 6 | 同上 `gas`（只取 6 个统计量） |
| 时序·送丝 | 6 | 同上 `wir` |
| 视觉·几何 | 4 | 该切片**自己的代表帧** → `vision_features_from_image` |
| 视觉·纹理 | 4 | 同上 |

**没有声音组**：切片 manifest 自己就写着 `audio.available = False`
（`splitting.map_window_to_modalities`），且音频上传已在 2026-10 收口拒收（`_AUDIO_EXTS` → `40000`）。
**没有真实源就不占维度**，而不是拿合成音频凑 6 维。

三条实现约束：

1. **只有一处分组定义**。`SAMPLE_GROUP_DIMS/NAMES` 从 `GROUP_DIMS/NAMES` **切片派生**
   （`[:-1]`），`unify`/`_concat_vector` 靠 `include_audio=False` 参数化——**不是 fork 出第二个函数**。
2. **切片定位读 manifest，不重算**。`splitting._window` 已把 `ceil(秒 × fs)` 写进
   `meta.signal.start_index/end_index`，那才是"切了什么"的权威记录；缺键才按
   `start_time/end_time` 现算，且一律 clamp（覆盖 `tail_policy="keep"` 的短尾片与手改过的 meta）。
   信号按 `meta.source.version_id` 取（不是 `task.version_id`）。
3. **视觉缺失按片降级，不整批失败**。视频是全站声明的增强模态（同 `_crop_seam_image` /
   `_extract_video_frames` 的取舍）：该片 `vision` 记 `missing` + 把服务端原因写进**该行** `warnings`，
   **照样落库**；任务仍 succeeded、`result.status="partial"`。**只有整批信号读不回来**才整批失败
   （那时 36 维全是 0）。
   `heuristic`（真帧 + 自家分割算法）**不算** partial——本部署没配正式视觉服务时按 non-real 算
   会让每一批都是 partial，那是噪音不是信号。计数分开给（`missing_vision` / `heuristic_vision`）。

## 5. 写路径

```
POST /split-tasks/{task_id}/sample-feature-extractions
  └ Job(type=sample_feature_extraction) → services.sample_features.extract_task_features
      ① 前置：splitting.segment_task_block_code（v3 + 已成功），不过 → 40000 + 特征口径措辞
      ② load_signal_bundle（按 manifest 的源版本）——读不回来整批失败
      ③ 逐片：读 meta.video.frame.object_key → 下帧 → vision_features_from_image(max_size=512)
             → 切父信号 → ts_features 逐通道 → unify(include_audio=False) → upsert
             每 20 片 commit 进度
      ④ 任务级产物 processed/{weld}/features/slice-features/{task_id}-{params_tag}.json
      ⑤ job.result / write_audit / mark_succeeded
```

- **失败清理只删本次写入的行**：重提取失败时上一次的成功结果必须完好——整批删掉会让
  "改个参数重跑失败"变成数据也没了。
- **不建数据版本**：这些特征的自然锚点是 `split_task_id`，不是焊缝数据版本。版本的幂等键是
  `(action, note, object_keys)`，切片侧没有能区分参数化的产物键，硬造一个只会让版本链多出
  "这版到底是哪个特征提取"的歧义。改为写**任务级产物**（键带 `params_tag`：换参数重跑不覆盖上一次）。
- **代表帧降采样 512px**：切片级每段各跑一次 `graycomatrix(levels=256)`，`vision_features_from_image`
  加可选 `max_size`（默认 `None` ⇒ 版本级数值逐字不变）。
- **成本**：N 次 MinIO GET + N 次视觉计算。Job 跑在**单线程执行器**里，200 片会让其它 job 排队
  （与长视频转码同性质），靠进度提交让等待可见。

## 6. 归一化：权威值存原始值

落库 `normalization` **恒为 `无`**。原因：`features._normalize` 作用在**单个向量**上——

- Z-Score 减掉该切片自己的均值、除掉自己的标准差 ⇒ **每个切片都变成零均值**，恰好抹掉
  区分切片的那批量（电流均值、RMS、气体/送丝水平）；
- Min-Max 同理把每片压到自己的 `[0, 1]`。

**标准化属于训练侧、应按 train 划分拟合**（**已实现，见 §6.1**）。归一化选择器只影响
**导出文件**——导出接口按请求参数重新算，不写回库。

### 6.1 训练前的逐维标准化（2026-10 已实现）

`torch_training.run()` 在张量化之前，用 `_fit_standardizer` **只在 train 划分上**拟合逐维
mean/std，再用同一组统计量**变换** train/val/test。两条不可退让的性质：

1. **只在 train 上拟合** —— 用全量（含 val/test）拟合等于把验证集分布信息漏进训练；
2. **跨样本拟合，而不是对单个向量做** —— 后者正是切片级刻意避免的（§6 上半段）。

**为什么必须做**：特征存的是原始值，"电流均值"那维是 **256 量级**（实测），
直接进 `Linear` 首轮 logits 爆掉、交叉熵上到 **1.06e12**。实测对比（同一条焊缝、同一个
数据集版本、50 轮）：

| | train loss 首 → 末 | val loss 首 → 末 |
|---|---|---|
| 标准化前 | 2327.67 → 0.60 | **1.06e12** → 1.11 |
| 标准化后 | 0.75 → 0.06 | **0.79** → 0.42 |

**拟合出的 mean/std 写进权重文件**（`feature_scaling: "train_split_zscore"` + `feature_mean`
+ `feature_std`）—— 将来做推理必须用**同一组**统计量预处理输入，否则分布对不上。
退化维度（train 上方差 ≈ 0）std 取 1、只做中心化，绝不除零。

**注意它不改善"样本太少"**：2 个验证样本上 metrics 仍无意义（现在会显示 1.0，那是噪声）。

## 7. 构建冻结与训练消费

- `datasets.run_build` 在造 `DatasetItem` 处挂 `features=features_by_sample.get(s.id)`
  （与 `annotations` 快照并排）。**缺特征不阻断构建**，但要 `logger.warning` 出 `N/M`。
- `_build_snapshot` 的 items 带 `features`（快照要自描述、要能在本地库丢了之后复现这一版输入——
  与当初把 `annotations` 放进来同一理由）。
- 版本详情加 `features_frozen`（与 `annotations_frozen` 同一三态）：`true`=全部有 / `false`=全无或混用 / `null`=无成员。
- `torch_training.load_real_examples` 返回 `(examples, label_names, feature_kind)`，口径**全有 / 全无 / 混用**三态：
  - 全有 → `slice_v1`，读快照里的 36 维；
  - 全无 → `legacy_summary`，回落旧的 8 维现算（**存量数据集因此零改动继续可训**）+ warning；
  - 混用 → **抛**并点名缺哪些（两种口径的向量长度不同，混进同一批张量化就炸）。
- `run()` 的输入维度**从数据来**（`len(examples[0].features)`，曾经写死 `nn.Linear(8, …)`），
  维度不一致直接报错；`input_dim` + `feature_kind` 存进权重文件。
- **训练准入**（`create_training_task`）加一条切片特征完整性检查：用 `datasets.feature_coverage` 判
  **全无放行、混用 40000 + 点名**——用户在**建 job 之前**拿到原因，而不是跑一半才炸。
  （注意：`features_frozen` 对"全无"和"混用"都是 `False`，所以准入必须用 `feature_coverage`。）

## 8. 前端

`analysis/features` 整个换成切片级工作台 `SampleFeatureWorkspace`（**路由/导航不变**）：

- **两段式**（同 `SampleAnnotationWorkspace`）：① 该焊缝可提取的分段任务列表（最新一张卡 +
  折叠的历史 + 删除）；② 进任务后：切片条（按 `BATCH_SIZE=40` 分批）+ 选中切片的 36 维细节
  + 归一化（**只影响导出**）+ 执行提取 + 导出 JSON/CSV + 「换个分段任务」。
- **props 没有 `selectedVersionId`**：单位是分段任务，不是焊缝版本。
- **无 mock 初始态**：初始一律空 + loading，失败走 `ErrorState`。本页此前是全局 mock 禁令的
  **唯一例外**（"特征表刻意保留 mock 初始"），这一版起**退休**。
- 代表帧 URL **只给选中那一片**签（几百片各签一次没有意义）；列表行只带 `frame_key`。
- 分段页新增入口「去提取切片特征」，与「去标注这批样本」一起走 **`navigate` 助手**
  （`SplitWorkspace` 新增必填 `navigate` prop），不再用 `window.location.hash`。

## 9. 迁移兼容

**纯 expand，不回填**：新表老代码不读、`dataset_items.features` 可空老代码忽略。

- 存量**分段任务**没有切片特征 → 需要时在页面重跑提取即可（原地 upsert）。
- 存量**数据集版本** `features` 全为 NULL → 训练走旧的 8 维现算口径，**零改动继续可训**。
- 一旦某版本是"混合"（部分成员有），训练**拒绝**并提示重建版本——这是刻意的：两种口径的
  向量长度不同，静默混用只会产出看不懂的模型。

**FK 级联陷阱（踩过）**：`SampleFeature.sample_id` / `split_task_id` 指向 `samples` / `split_tasks`，
而这些表之间只有**裸外键列、没有 `relationship()`**——SQLAlchemy 的工作单元推不出删除先后。
`delete_split_task` 与 `delete_record` 的级联必须**显式 `session.flush()`**，否则 MySQL 报
`1451 Cannot delete a parent row`（SQLite 默认不校验外键，离线用例照样绿——
`test_sample_features_e2e.py` 的 engine 因此开了 `PRAGMA foreign_keys=ON`）。

## 11. 附：单焊缝的划分策略（2026-10，与本特性同批）

特征提完之后，"能不能训练"卡在了划分上，故一并改掉。**无表结构变更**（`dataset_versions.split`
是既有 JSON 列，只是多一个键）。

### 问题

划分原先是**按焊缝分组**的（同焊缝整体进一个分片，防泄漏），而 `run_build` 在只有 1 组时
把整条焊缝丢进 train、`val = 0`，训练准入又硬要求 `val > 0` → **单焊缝数据必然 `40000`
「没有验证集样本」**。也就是说那条"组数 <3 时退化为 train / train+test"的路径产出的版本
**根本训不了** —— 既没泄漏，也用不了，等于绕了一圈的拒绝。

### 改法

| 候选来源 | 策略 | 原因 |
|---|---|---|
| ≥2 条焊缝 | `by_weld`：seed=42 打乱**组序**后 8:1:1 | 跨焊缝指标可信 |
| 只有 1 条焊缝 | `within_weld`：按 `start_time` 排序后切前/中/后三段 | `val` 非空 → 能训 |

- `n == 2` 由 train/**test** 改为 train/**val** —— 训练准入查的是 `split["val"]`，给 test
  等于那种版本也训不了；两个焊缝足以做跨焊缝验证。
- **焊缝内划分不许 shuffle**：相邻窗口来自同一段连续信号、同一台机器、同一次作业，打散等于
  把验证窗口的邻居放进训练集。按时间切至少让边界两侧尽量远离。
- 样本过少时优先保 train 与 val 各一个（丢 test）；**只有 1 个样本时仍给 train、`val = 0`，
  如实让准入拒绝**（不硬凑）。

### 代价必须可见

焊缝内划分得到的指标量的是**焊缝内泛化**，不能当跨焊缝性能汇报。故：

- `split_counts["strategy"]` 落库（`{"train":n,"val":n,"test":n,"strategy":"within_weld"}`）；
- 前端「训练数据准备」用 `WithinWeldWarning` 在结果面板上方给**醒目警告**；
- 顺带修了那句写错的文案：原文"按**样本**分组"实际一直是"按**焊缝**分组"。

**`strategy` 是这条护栏的唯一出口** —— 去掉它，半年后就会有人拿焊缝内验证准确率去汇报
跨焊缝性能。回归：`tests/test_dataset_members.py`（纯规则 + 连续块不许打散 + 边界）
与 `tests/test_sample_features_e2e.py`（单焊缝版本现在能过准入；1 个样本仍被拒）。
