# 焊接数据智能分析与 AI 建模平台

这是一个面向焊接工艺研究、质量分析、数据治理和 AI 建模的前端静态原型。当前阶段重点验证页面信息架构、业务流程和交互表达，页面中的统计、图表、核验结果、训练指标等均为演示数据。

## 页面结构

左侧导航保持四个一级入口：

1. **数据总览**：只展示全局数据资产、质量分布和趋势，不直接操作某条焊缝数据。
2. **数据中心**：围绕单条焊缝数据进行列表、登记、核验和版本管理。
3. **分析与标注**：围绕选中的焊缝完成多模态对齐、信号分析、数据切分和标注。
4. **模型中心**：管理模型仓库、训练任务、测试评估和推理验证。

页面顶部已保持精简，不显示全局搜索、工作空间面包屑和当前页面名称；页面自身通过标题和 Tab 表达上下文。

## 核心业务逻辑

平台采用“先选数据，再处理数据”的上下文模式。

```text
数据总览
  ↓
数据中心 / 数据列表
  ↓
筛选并选择一条焊缝数据
  ↓
数据登记 / 数据核验 / 数据版本
  ↓
分析与标注
  ↓
多模态对齐 → 信号分析 → 数据切分 → 数据标注
  ↓
模型中心
  ↓
模型仓库 → 模型训练 → 测试评估 → 推理验证
```

### 数据选择规则

- 数据登记、数据核验、数据版本都必须先在数据列表中选择一条数据。
- 未选择数据时，相关 Tab 置灰；如果通过其他方式进入，会显示“请先选择一条数据”。
- 当前选中的数据通过应用级状态保存，数据中心和分析与标注共用该上下文。
- 当前选中数据会在页面中显示焊缝 ID、数据来源、焊机型号、最新版本和核验状态。

### 数据列表规则

- 主列表以焊缝 ID 为维度去重。
- 列表只显示每条数据的最新版本，不重复展示历史版本。
- 历史版本通过“数据版本”页面查看。
- 当前原型支持以下筛选：
  - 焊缝 ID / 登记编号关键词
  - 数据来源
  - 焊机品牌
  - 核验状态展示

后续接入后端时，筛选条件应映射到数据查询接口，而不是在前端加载全部数据后过滤。

### 数据登记规则

数据登记不是独立的新建页面，而是当前选中数据的登记信息查看和编辑页面，包含：

- 登记编号
- 数据来源
- 采集时间
- 焊机品牌与型号
- 焊接方法
- 板材材质与厚度
- 工艺参数
- 原始文件和多模态文件
- 登记人及登记时间

### 数据核验规则

数据核验针对当前选中数据和当前版本执行，展示 15 项规则的通过、警告或失败状态，并关联核验时间、异常原因和核验报告。

### 数据版本规则

每条焊缝数据拥有独立版本链，例如：

```text
v1.0 原始数据
  ↓
v1.1 去噪处理
  ↓
v1.2 多模态对齐
  ↓
v1.3 人工修正
```

主数据列表只显示最新版本，版本页面负责查看历史版本、处理动作、创建人和当前版本状态。

### 分析与标注规则

分析与标注页面默认要求先选择数据。选中后依次进入：

1. 多模态对齐：视频、时序信号、音频和红外数据统一时间轴。
2. 信号分析：时域、频域、STFT、DWT、UI 相图、PDD 和异常区段。
3. 数据切分：固定频率、事件规则、起收弧缓冲和任务格式。
4. 数据标注：图像框选、缺陷标签、AI 预标注和人工修正。

每个步骤都继承同一条焊缝数据和版本上下文。

## 当前前端实现

- 技术栈：React + TypeScript + Vite + lucide-react
- 主要页面代码：[src/App.tsx](src/App.tsx)
- 全局样式：[src/index.css](src/index.css)
- 当前数据为组件内静态演示数据
- 当前交互状态使用 React `useState` 管理
- 生产环境需要将数据记录、版本、核验、标注和模型任务替换为后端接口

## 后续开发建议

建议后续按以下顺序接入真实能力：

1. 抽离 `DataRecord`、`DataVersion`、`ValidationResult`、`AnnotationTask`、`ModelTask` 类型。
2. 建立以 `dataId` 和 `versionId` 为核心的数据接口。
3. 将当前应用级选中数据替换为路由参数或全局状态管理。
4. 将数据列表筛选改为服务端分页查询。
5. 补充操作审计、权限控制和版本回滚接口。
6. 接入真实视频、时序数据和模型任务状态。
