# 焊接工艺分析和建模机器学习平台

这是一个面向焊接工艺研究、质量分析、数据治理和 AI 建模的全栈系统。当前已进入真实系统功能验收阶段：前后端 API、MySQL、MinIO、登录、异步任务和报告导出已经打通，真实信号导入、信号分析、特征提取和分析报告已经走通。部分切分、标注、训练、测试和推理的算法计算内核仍为演示/模拟实现，但其业务任务编排、状态持久化、结果回填和产物关联按真实系统验收。

## 页面结构

左侧导航保持四个一级入口：

1. **数据总览**：只展示全局数据资产、质量分布和趋势，不直接操作某条焊缝数据。
2. **数据管理**：围绕单条焊缝数据进行列表、数据集、登记、核验和版本管理。
3. **分析与标注**：围绕选中的焊缝完成多模态对齐、起收弧识别、数据切分和标注。
4. **模型中心**：管理模型仓库、训练任务、测试评估和推理验证。

页面顶部保持精简，不显示全局搜索；数据集层级页面通过页面标题、面包屑和上下文卡表达当前数据集、版本及成员位置，其他工作区通过页面标题和局部导航表达上下文。

## 核心业务闭环与角色主路径

平台采用“先明确数据上下文，再处理数据”的上下文模式。核心业务闭环为：

```text
数据集/焊缝数据 → 数据版本 → 核验 → 分析与标注
  → 固定数据集版本 → 模型训练 → 测试评估 → 推理
```

不同角色可以从不同入口进入，也可以跳过已经完成的步骤；但所有下游操作必须继承并显示正确的数据、版本、数据集和任务上下文。

```text
数据总览
  ↓
  数据管理 / 数据列表
  ↓
 筛选并选择一条焊缝数据
  ↓
 数据登记 / 数据核验 / 数据版本
  ↓
 分析与标注
  ↓
 多模态对齐 → 起收弧识别 → 数据切分 → 数据标注
  ↓
 数据集构建 → 数据集审核 → 固定数据集版本
  ↓
 模型中心
  ↓
模型仓库 → 模型训练 → 测试评估 → 推理验证
```

### 数据选择规则

- 数据核验、数据版本必须先选择一条数据；**数据登记是新建操作**，不要求先选。
- 未选择数据时，相关 Tab 置灰；如果通过其他方式进入，会显示“请先选择一条数据”。
- 当前选中的数据通过应用级状态保存，数据管理和分析与标注共用该上下文。
- 当前选中数据会在页面中显示焊缝 ID、数据来源、焊机型号、最新版本和核验状态。

### 数据列表规则

- 主列表以焊缝 ID 为维度去重。
- 列表只显示每条数据的最新版本，不重复展示历史版本。
- 历史版本通过“数据版本”页面查看。
- 当前系统支持以下筛选：
  - 焊缝 ID / 登记编号关键词
  - 数据来源
  - 焊机品牌
  - 核验状态展示

后续接入后端时，筛选条件应映射到数据查询接口，而不是在前端加载全部数据后过滤。

### 数据登记规则

数据登记把单个数据（文件 + 元数据）作为新记录登记进所选数据集：提交时自动生成登记编号（`REG-YYYYMMDD-序号`）与焊缝 ID，并生成 v1.0「原始数据」版本；原始文件按类型分 4 个独立上传区（时序 CSV / 图片 / 视频 / WAV），提交要求至少上传一个文件；已登记记录可经后端 `PATCH /registrations/{id}` 编辑登记信息。登记信息包含：

- 登记编号
- 所属数据集（上传必须归属一个数据集，作为分析与标注的入口维度）
- 数据来源
- 采集时间
- 焊缝/批次名称
- 焊机品牌与型号
- 焊接方法
- 板材材质与厚度
- 工艺参数
- 原始文件和多模态文件
- 登记人及登记时间

### 数据核验规则

数据核验针对当前选中数据和当前版本执行，展示 15 项规则的通过、警告或失败状态，并关联核验时间、异常原因和核验报告。

### 数据版本规则

每条焊缝数据拥有独立版本链，例如：

```text
v1.0 原始数据
  ↓
v1.1 去噪处理
  ↓
v1.2 多模态对齐
  ↓
v1.3 人工修正
```

主数据列表只显示最新版本，版本页面负责查看历史版本、处理动作、创建人和当前版本状态。

### 分析与标注规则

分析与标注采用**数据集优先**的两级选择入口：每条焊缝上传时归属一个数据集，分析页先选定数据集，再在数据集内选择一条焊缝；数据集内未核验通过（待复核/异常）的焊缝置灰不可选。选中后依次进入：

1. 多模态对齐：视频、时序信号、音频和红外数据统一时间轴。
2. 起收弧识别：时域、频域、STFT、DWT、UI 相图、PDD 和异常区段。
3. 数据切分：固定频率、事件规则、起收弧缓冲和任务格式。
4. 数据标注：图像框选、缺陷标签、AI 预标注和人工修正。

每个步骤都继承同一条焊缝数据和版本上下文。数据集范围指上传归属的容器维度（`data_records.dataset_id`），分析仍作用于焊缝最新版本；数据集版本快照是训练侧的固定成员清单，不用于限定分析候选。

### 数据集维护逻辑

数据集是连接“分析与标注”和“模型训练”的中间业务实体，不直接等同于原始数据列表。数据处理层级为：

```text
单条焊缝数据 → 数据版本 → 切分样本/标注结果 → 数据集版本 → 训练任务/测试任务 → 模型版本
```

数据管理新增“数据集”Tab，当前系统包含：

- **数据集列表**：展示数据集名称、任务类型、样本量、标注完成度、当前版本和状态。
- **新建数据集**：页面入口已预留，后续可支持按数据筛选、按标注任务或手动选择样本创建。
- **数据集详情**：查看样本统计、训练/验证/测试划分、数据质量和最近更新时间。
- **数据集版本**：每个版本对应固定样本清单，支持查看版本变更，并预留新建版本入口。
- **数据血缘**：展示原始焊缝、标注任务、数据集版本和模型训练之间的关联关系。

数据集状态包括“标注中”“可训练”等。只有“可训练”的数据集版本才能进入模型训练；模型训练和模型测试页面均显示当前选中的数据集版本及固定样本数量，避免直接使用会变化的实时数据列表。

数据集版本保存训练集、验证集、测试集的固定成员清单。原始数据或标注发生变化时，不覆盖旧版本，而是生成新的数据集版本，以保证历史训练结果可复现。

### 数据集输入维度与模型适配

当前数据集支持以下输入维度，但单条数据不要求全部具备：

```text
Voltage
GasSpeed
Current
Molten_feature
Sound_feature
焊缝照片
熔池视频
```

当前系统按三种模型任务定义最低输入要求：

| 模型任务 | 必须输入 | 可选输入 | 主要输出 |
|---|---|---|---|
| 焊接异常检测 / 时序分类 | `Current`、`Voltage`、`GasSpeed` | `Sound_feature`、`Molten_feature` | 正常、电弧不稳、飞溅倾向、气孔倾向、熔透不足 |
| 熔池分割 / 语义分割 | 熔池视频，切分后形成图像帧；同时需要像素级掩膜 | 焊缝照片、`Molten_feature` | 熔池区域、熔透区域、焊缝路径、飞溅区域 |
| 多模态质量预测 / 回归 | 至少两类已对齐模态，最低包含 `Current`、`Voltage` | `GasSpeed`、`Molten_feature`、`Sound_feature`、焊缝照片、熔池视频 | 熔深、熔宽、质量评分或工艺状态 |

页面中的“输入数据维度”区域会区分“已具备”“缺失”和“当前任务必需”。字段缺失不自动代表数据集不可用，只有缺失当前模型的必需输入时才不能进入该模型训练。

“模型适配检查”会根据任务动态检查：

- 时序信号是否完整、采样率是否一致、时间轴是否对齐；
- 熔池视频是否已切分为图像帧，图像与像素级掩膜数量是否一致；
- 标签是否完整并完成审核；
- 训练、验证、测试集是否已经固定；
- 是否按照焊缝 ID 分组，避免同一条焊缝的不同视频帧泄漏到不同数据集分片。

数据集详情中的训练/验证/测试数量采用“按焊缝 ID 分组”的固定策略，而不是对视频帧或样本随机切分。这样可以避免同源样本同时出现在训练集和测试集，造成评估指标虚高。

## 当前系统实现状态

- 技术栈：React + TypeScript + Vite + lucide-react
- 主要页面代码：[src/App.tsx](src/App.tsx)
- 全局样式：[src/index.css](src/index.css)
- 页面主要数据已通过 `src/api/` 接入后端 `/api/v1`，组件状态使用 React `useState` 管理。
- 真实信号相关页面优先使用真实导入结果；部分算法页面仍会返回演示计算结果，但必须标识其能力边界。
- API 失败时页面显示明确错误或空状态；不得把失败静默伪装成成功，也不得把静态演示数据冒充真实业务结果。

## 后续开发建议

建议后续按以下顺序接入真实能力：

1. 抽离 `DataRecord`、`DataVersion`、`Sample`、`AnnotationTask`、`Dataset`、`DatasetVersion`、`DatasetItem`、`ModelTask` 类型。
2. 建立以 `dataId`、`versionId`、`datasetId` 和 `datasetVersionId` 为核心的数据接口。
3. 将当前应用级选中数据替换为路由参数或全局状态管理。
4. 将数据列表筛选改为服务端分页查询。
5. 补充操作审计、权限控制和版本回滚接口。
6. 接入真实视频、时序数据和模型任务状态。
7. 实现数据集构建任务、样本质量检查、数据划分固定和数据血缘查询。

## 本地运行

后端先起（连接真实 MySQL/MinIO，启动时自动 seed 管理员与演示数据）：

```bash
cd backend && uv sync && uv run uvicorn app.main:app --reload
```

前端随后（`npm run dev` 走 `/api` proxy 转发到 `http://localhost:8000`）：

```bash
npm install
npm run dev
```

登录账号见根 `.env` 的 `ADMIN_USERNAME`/`ADMIN_PASSWORD`（本地演示默认 `admin`/`admin123`，生产必须改）。

构建检查（前端）：

```bash
npm run typecheck
npm run build
```

后端测试（SQLite 内存，不连远程库）：

```bash
cd backend && uv run pytest
```

## 部署

部署采用 Docker 私有化方案：推送到 `main` 后，GitHub Actions（`.github/workflows/deploy-docker.yml`）先执行前端 lint/typecheck/build 校验，再构建镜像推送到阿里云 ACR。服务器先启动候选容器执行 `alembic upgrade head`，并通过数据库、迁移版本、关键表和 MinIO readiness；预检成功后才切换生产容器，正式容器失败会自动恢复上一容器。FastAPI 同时服务 `/api` 与前端静态文件。数据库迁移必须遵循 expand/contract；容器回滚不会自动 downgrade 数据库。详见 `docs/superpowers/specs/2026-08-26-docker-cicd-design.md`。
