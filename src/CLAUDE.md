# CLAUDE.md — src/

前端源码（React 18 + TypeScript + Tailwind）。

- `main.tsx`：React 入口，挂载 `App`。
- `App.tsx`：主应用（单文件）。含四个一级模块——数据总览、数据中心、分析与标注、模型中心；实现侧边栏导航、数据集列表→概览→数据列表→数据详情层级、"先选数据"上下文状态。数据详情中的 `RawSignalPreview` 复用 `/signals` 接口展示真实多通道原始波形，失败时明确回落演示波形。数据集列表不显示全局选中数据上下文条；点击侧边栏“数据中心/数据集”可从任意数据集子页面返回数据集列表。版本列表的“查看”打开右侧 `VersionDetailDrawer`：焊缝版本读取版本详情与核验结果，数据集版本读取固定快照详情。**Task 21 起总览页与数据列表已接 API**（`Overview` ← `getDashboardData`，内部聚合调用 `getStats/getAttributes/getDistributions/getProjects` 并使用 5 分钟浏览器缓存；`ManagementFiltered` ← `listWelds` 服务端筛选分页；`SelectionContext` ← `getWeld`）；**Task 22 起数据中心其余页已接 API**——`Registration`（登记提交 ← `createRegistration`，文件上传 ← `uploadFile`(<100MB)/`presignUpload`(≥100MB)+PUT，**PUT 后先查 `res.ok`，失败抛错丢弃 object_key**，上传后 ← `attachRawFiles`，最近登记 ← `listWelds({tab:'recent'})`）、`Validation`（挂载 ← `getWeld` 取 `latest_version_id` → `getValidation`，执行 ← `runValidation`）、`VersionPanel`（只读版本链 ← `listVersions`）、数据集（入口为 `data-center/datasets`；`DatasetWorkspace` 按**数据集列表 → 数据集概览 → 当前版本成员 → 成员详情**层级展示，无独立全局数据列表导航：列表/新建 ← `listDatasets`/`createDataset`，概览 ← `getDataset`+`getDimensions`+`getReadiness`+`listDatasetVersions`+`getLineage`，成员 ← `listDatasetVersionItems` 服务端分页/筛选，新建版本 ← `createDatasetVersion`；成员详情设置 `selectedDataId`，继续复用核验/版本/分析流程；训练/测试数据集条 ← `listDatasets()[0]`）。**Task 23 起分析与标注页已接 API**：`AnalysisSelect` ← `listCandidates`；`Alignment`（含 splitOnly 变体）← `createAlignmentTask/createSplitTask` + `useJob`（轮询对齐/切分 Job，成功渲染 events/sample_count；**切分页缓冲秒数可编辑，`keep_event_buffer` 按准确数值透传，关闭时传 0**）；`AdvancedWeldAnalysis` ← `getSignals`（挂载/滤波变化时拉取，四通道常驻、勾选仅本地过滤）+ `getAnalysisMode`（psd/stft/dwt/wavelet/phase/pdd，mode/目标通道/滤波联动）+ `getAnalysisResult`（稳定度/三类占比/异常区段 chips）；`Annotation` ← `listLabelCategories` + 挂载时 `createAnnotationTask({source:'manual',name:'AN-演示'})`（best-effort）+ `useJob` → `listAnnotationSamples/getAnnotationSample`，AI 预标注 ← `aiPretag`、保存 ← `saveAnnotation`、样本图 ← `getFileUrl`；`FeatureExtraction` ← `extractFeatures`（"执行提取"工具栏按钮，归一化/格式读 UI 状态，L2 范数↔L2 映射），三类特征表 + 统一向量条由结果映射（保留 mock 初始/兜底）。**Task 24 起模型中心已接 API**：`ModelRepository` ← `listModels`（汇总总数/生产候选/最近训练/GPU + 模型卡片，`metric` dict→`modelMetricText` 文案），「新建模型」← `createModel` + 仓库刷新计数（`refreshKey`）；`Training` ← `listDatasets()[0]` 当前版本 + `listModels` 解析基础模型（best-effort），开始训练 ← `createTrainingTask`（超参读表单 `config` state）+ `useJob` → 指标/损失曲线（`lossToPath` 数据驱动 SVG path）/进度，日志 ← `getTrainingLogs`；`ModelTest` ← `createTestTask` + `useJob` → 指标 + 2×2 混淆矩阵；`InferencePanel` ← 上传 `uploadFile`(<100MB)/`presignUpload`(≥100MB)+PUT（**PUT 后先查 `res.ok`，失败抛错丢弃 object_key**）→ object_key → `createInferenceTask` + `useJob` → 类别/置信度/耗时；`Toolbar` 导出 ← `exportReport`（type 按页映射 data-list/validation/analysis/annotation/features/test），返回 url → `window.open`。接线模式：总览通过 `getDashboardData` 读取四个真实聚合接口，使用浏览器缓存（5 分钟 TTL）避免每次刷新重复请求；缓存失效后重新请求并覆盖缓存，接口失败显示明确错误状态，不使用 mock - `App.buffer-regression.test.mjs`：Node 内置测试；静态断言 `Alignment` 切分页暴露 `bufferSeconds` 可编辑输入，且 `createSplitTask` 不再把 `keep_event_buffer` 硬编码为 `0.2`。

坑/限制：
- `App.tsx` 是单文件大组件，改动时不要破坏现有信息架构（四个模块 + 先选数据模式）。接线时只换数据源，不改 JSX/className。
- 总览/列表接 API 时的映射约定：分布/缺陷 `tone` 用 `donutPalette`（`src/App.tsx`）按序取色（后端不输出颜色）；多模态 token 经 `modalityMeta` 映射中文 label/icon/desc（video/timeseries/audio/infrared 等）；`Project.progress`(0-100) 字符串化为 `"68%"`、status→tone（标注中→blue，可训练/已完成→green，其余→orange）；`listWelds` 的 `source`/`brand` 为前缀匹配、`tab` 传 `全部最新数据/待核验/已归档`（后端未知 tab 视为不过滤），分页 `page/page_size`。
- 数据集层级（Task 2–4 + final fix）：`DatasetWorkspace` 严格按**数据集列表 → 数据集概览 → 当前版本成员 → 成员详情**呈现，列表页不内嵌概览；真实 `listDatasets` 成功后，选中版本必须重绑定为所选数据集的 `current_version_id`（无当前版本则为 `null`），不得保留 mock 版本。`DatasetDetail` 的版本列表初始必须为空（或仅 dataset-specific 安全回退），`listDatasetVersions` 失败后也不得回灌 `mockDatasetVersions`。无当前版本仅显示“创建数据集版本”空状态，不显示 mock 版本入口。`DatasetItemRow` 是固定 `dataset_items` 快照中的样本粒度行，筛选 `q/quality/split` 必须由 `listDatasetVersionItems(datasetId, versionId, params)` 请求服务端；成员页训练/验证/测试总数取 `getDatasetVersion(...).split`，不从当前分页行归纳；`DatasetRecords` 的版本摘要只能来自当前 `dataset/versionId` 的真实详情，失败时必须显示明确不可用状态，不能借用别的版本 mock 摘要。版本切换清空成员与 `selectedDataId`；成员 API 失败保留 mock 行并给出非阻塞提示。成员详情仅接受行中的真实 `weld_id`，以其调用 `getWeld` 并显示登记编号、当前版本和核验状态及数据集/版本/划分上下文，绝不以 `sample_id` 代替焊缝 ID。`data-center/registration` 是新建操作，绝不加入 `routesRequiringData`。
- 数据中心接 API 的映射约定（Task 22）：数据集行 `DatasetRow` 由 `Dataset` 派生——`split` 空/未构建→`'—'`（详情 `split` 同），`progress`→`"96.8%"`，`status`→tone（可训练→green，其余→orange），`source` 后端无此字段统一 `'多模态数据'`；核验规则由 `ValidationRuleResult.status`(passed/warning/failed) 映射图标/文案/状态色（失败→红、警告→橙、通过→绿），汇总状态 `failed>0→异常 / 仅警告→待复核 / 否则→核验通过`；维度由 `DimensionStatus.status`(已具备/必需/缺失)+`required` 驱动；适配检查 `ReadinessCheck` 的 `checks[].passed` 决定每行图标；数据集版本 `DatasetVersion` 无 label/action 字段，快照行标题用 `数据快照 · {item_count} 条样本`，当前版本按 `detail.current_version_id` 判定；血缘 `LineageNode` 按 `type` 映射图标与后缀（records→条 / training_tasks→次 / 其余→个）。
- 分析页接 API 的映射约定（Task 23）：通道 id `cur/vol/gas/wir` 前后端一致，后端不输出颜色→`chanColor` 按 id 映射；`getSignals` 返回 `values` 已由 api 层抽稀 ≤512，`toPath` 按 `values.length` 归一化横轴（勿再按 mock 的 `SAMPLES`）；六种图表组件（`PsdChart/StftHeatmap/DwtChart/WaveletDecomp/PhasePlot/PddChart`）都改为吃后端数组（`freqs/psd`、`magnitude`、`bands+approx`、`bands`、`current+voltage`、`bins+counts+kde`），未取到 API 时用 `values` 走原内部计算兜底（SVG 结构不动）；`DwtChart`/`WaveletDecomp` 取到 API 后标签用后端 `band.name`（D1..D4+A4 / L1..L5），无 API 才用内部计算标签；滤波在 signals/mode 请求带 `filter_type/cutoff/cutoff2` 时由后端计算（`filter_type` 逐字对齐 `filterTypes`），前端不再本地 `applyFilter`（已删除）；标注页 manual 源标注任务无样本（后端只给 split_task 归属样本），样本/图取不到时回落 mock `labelImage`；AI 预标注触发挂在标注板工具栏 icon-button（`title="AI 预标注"`）。
- `package.json` 里的 `@supabase/supabase-js` 依赖当前未使用。
- 接入后端时：接口走 `src/api/`，相对路径 `/api/v1/...`（契约见 `docs/API接口清单.md`）；开发环境由 `vite.config.ts` 的 `/api` proxy 转发到 `http://localhost:8000`，生产同源。不要重写 `App.tsx`。
